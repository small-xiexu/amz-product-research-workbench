## 输出（4 个深度分析字段）

写入 `analysis/integrated_operator_judgment.json` 的以下字段。**每个字段必须逐一填写，不得合并或省略。**

### `voc_to_spec` — VOC→规格推导链

P0/P1 痛点 → 具体产品规格要求 → 竞品对标差距 → 差异化机会。

```json
"voc_to_spec": [
  {
    "dimension": "痛点维度名",
    "priority": "P0 | P1 | P2",
    "issue_description": "竞品出了什么问题（基于评论原文的运营解读）",
    "spec_requirement": "产品应该做到什么规格",
    "benchmark_gap": "当前竞品在此维度的普遍水平",
    "differentiation_opportunity": "差异化机会的具体描述"
  }
]
```

### `keyword_strategy` — 关键词分层策略

主攻意图词 / 可测词 / 明确否定词的分层运营逻辑。

```json
"keyword_strategy": {
  "primary_attack": [
    {
      "keyword": "核心词",
      "monthly_search_volume": 12000,
      "cpc": 0.96,
      "strategy_rationale": "为什么是主攻词、如何投放"
    }
  ],
  "testable": [
    {
      "keyword": "测试词",
      "monthly_search_volume": 800,
      "cpc": 0.45,
      "strategy_rationale": "为什么可测、怎么测"
    }
  ],
  "negative": [
    {
      "keyword": "否定词",
      "strategy_rationale": "为什么否定、不匹配什么意图"
    }
  ],
  "strategy_note": "整体关键词策略一句话总结"
}
```

**冷启动流量现实检查（强制）**：当推荐路线的最核心攻击词（`primary_attack` 中月搜最高的词）月搜 < 500 时，必须在 `keyword_strategy.strategy_note` 中显式写出该路线的冷启动流量数学：

> 该路线核心词月搜仅 N，折合每月自然曝光约 N×2、自然访客约 N×2×预估CTR%、自然成交约 访客×预估CVR%。前期流量完全依赖泛词溢出和广告拉新，无独立搜索心智。广告投产比可能在前 3-6 个月承压。

此规则确保运营不会被"转化意愿极强"的信号误导而忽略体量现实。

### `risk_mitigation` — 风险缓解

每个高优先级风险的真实运营含义和具体缓解路径。内部可保留优先级枚举，解释文字必须写成运营可读表达。

```json
"risk_mitigation": [
  {
    "risk_name": "风险名",
    "severity": "高 | 中 | 低",
    "operational_meaning": "这个风险对运营的实际影响",
    "mitigation_path": "具体缓解路径（不说空话如"注意合规"）",
    "evidence_basis": "证据来源"
  }
]
```

### `validation_roadmap` — 验证路线图

按时间线组织的验证计划，每步有明确决策条件。不是 N 个平铺的"下一步"。

```json
"validation_roadmap": [
  {
    "phase": "阶段名",
    "actions": ["具体动作1", "具体动作2"],
    "exit_criteria": "通过标准",
    "if_fail": "不通过怎么办"
  }
]
```

**运营前置条件（强制自检）**：

设计阶段时，必须确保每个阶段引用的亚马逊能力在该阶段开始前已解锁。以下是关键前置依赖：

| 亚马逊能力 | 前置条件 | 解锁耗时 |
|---|---|---|
| A+ 页面（A+ Content） | 品牌注册（Brand Registry）已完成 | 品牌注册审核 2-15 工作日 |
| Vine 计划 | 品牌注册已完成 | 同品牌注册 |
| 品牌旗舰店（Brand Store） | 品牌注册已完成 | 同品牌注册 |
| 品牌分析报告（ABA） | 品牌注册已完成 | 同品牌注册 |
| 品牌注册（Brand Registry） | 美国商标已下证（USPTO Registered） | 商标申请到下证 8-14 个月 |
| Sponsored Brands 广告 | 品牌注册已完成 | 同品牌注册 |

**阶段排序铁律**：

1. **品牌注册必须在首次使用 A+/Vine/品牌旗舰店的阶段之前完成。** 如果阶段 N 的 actions 中包含 A+页面、Vine计划、品牌旗舰店、品牌分析报告中任意一项，则品牌注册必须出现在 ≤ N 的阶段中。
2. **商标申请（如果尚未下证）属于阶段 0（决定做之前）。** 商标从申请到下证需 8-14 个月，不可压缩。
3. **阶段 1 默认包含上线前所有准备工作。** 品质工程验证期间可并行推进品牌注册（等待 USPTO + 亚马逊审核），不额外消耗时间。
4. **不允许出现"先做 A+、后补品牌注册"的时序。** 这是操作上不可能的动作。

**自检方法**：写完 `validation_roadmap` 后，按阶段从前到后扫描每个 action，如果发现某个 action 需要品牌注册能力，向前搜索是否已有"完成品牌注册"的 action。如果没找到，将品牌注册插入到最早需要它的阶段之前。

## VOC 不足降级模式

当 VOC 有效评论 < 30 条时：

- `voc_to_spec` 仍然输出（基于有限样本），但在 `issue_description` 中注明"基于有限样本（N 条评论）"
- `voc_to_spec` 每条增加 `"data_note": "样本不足，评论采集完成后重新推导"`
- 不因此跳过或省略 VOC 分析

## 分析要求

### 必须回查原始证据

- 关键词策略 → 查 `search_demand` 的搜索量、CPC、竞争度原始值
- VOC 痛点 → 查原始评论原文（`quote` 字段），确认频次 ≥ 3 且有 ASIN 覆盖

### 风险不列空话

"注意合规"、"控制成本"、"关注竞争" 类通用建议不写出。每个风险必须说明：
- 这个风险在**这个品类**具体意味着什么
- 缓解路径具体到可以执行的步骤

### 面向报告的话术边界

- `voc_to_spec.priority` 可以按契约写 `P0/P1/P2`，但 `issue_description`、`spec_requirement`、`operational_meaning`、`mitigation_path`、`validation_roadmap` 中不得裸露 `P0安全风险`、`P0痛点` 等内部标签。
- 写"必须验证的安全可靠性问题""用户高频核心痛点""重点优化项"，不要写"生死考验""摧毁 ASIN""赌博"等惊吓式表达。
- 风险描述采用"证据 → 影响 → 验证/缓解动作"结构，不写空泛威胁。
- 本项目当前判断"市场能不能继续看"，不输出 COGS、FOB、采购价、供应商报价、毛利率、FBA 费用、1688 实际报价等后置落地变量，也不得把这些缺失写成阻塞项。

## 禁止

- 不输出 final_verdict、Go/No-Go 判断
- 不涉及路线推荐、竞品对标、价格带解读
- 不生成 HTML 或 report_data.json
- 不新增证据包外的数字（估算必须标注假设前提）

以下字段路径会被 `validate_judgment.py --check-placeholders` 校验，**路径和格式不得偏离**：

| 你写什么 | 脚本怎么读 | 常见错误 |
