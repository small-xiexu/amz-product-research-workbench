# 亚马逊运营选品自查工具技术方案

更新日期：2026-06-07

## 技术定位

做一套基于卖家精灵数据的亚马逊选品全流程报告系统。V1 数据接入优先使用卖家精灵手动导出的 Excel/CSV 或整理表；后续自动化只保留卖家精灵 MCP 路线，不再规划 HTTP API 接入。

它不是自动推荐爆品的工具，也不是单纯的调研材料生成器。核心目标是让同一套数据直接生成报告和看板：

`边界 -> 市场 -> 竞品 -> 痛点 -> 利润 -> 退货 -> 知产/合规 -> 状态 -> 下一步`

产品形态分三步走：

| 阶段 | 形态 | 目标 |
|---|---|---|
| 阶段 1 | Agent Skill + 本地报告生成器 | 跑通数据采集、规则判断、Excel/Markdown/HTML 输出 |
| 阶段 2 | 轻量网页工作台 | 支持补数、删改竞品、调利润参数、重生成报告 |
| 阶段 3 | 完整选品应用 | 支持历史调研库、多品类横向比较、评论深挖、复盘和协作 |

V1 先做 Skill + 本地报告生成器。深度评论、图片/A+、推广节奏和完整网页工作台放到后续版本。

## 架构分层

| 层级 | 职责 | 首版形态 |
|---|---|---|
| Agent Skill | 编排流程、生成卖家精灵导出清单、执行硬性规则、生成分析结论 | `SKILL.md` + references |
| 数据管道 | 读取卖家精灵导出文件、MCP 数据、运营手填和评论插件，清洗标准化 | 脚本 + `research_package.json` |
| 计算规则 | 利润、头程、竞品池、退货、知产/合规、状态规则 | 独立规则文件 + 脚本 |
| 报告引擎 | 生成 Markdown 主报告、摘要、HTML 看板、Excel 数据底表 | 本地渲染脚本 |
| 工作台 | 查看结果、补字段、复核竞品、调整状态、重新生成报告 | V2 轻量网页 |

Skill 是流程大脑，不承载全部产品能力。长期目标是选品工作台，Skill 负责 AI 编排和判断规则。

## 设计原则

| 原则 | 说明 |
|---|---|
| 决策优先 | 页面和文档都围绕判断、补数、复盘 |
| 人主导关键判断 | 市场边界、竞品是否合理、供应链能力、最终状态由运营确认 |
| 证据链优先 | 每个判断要能追溯到数据表、评论、工具来源或运营手填项 |
| 先轻后重 | V1 只跑初筛，确认值得继续后再做评论深挖和内容推广分析 |
| 风险前置 | 专利、商标、版权、合规认证在早期给风险提示 |
| 不替代专业意见 | 知产和合规只做初筛，不替代律师、代理机构、检测机构、Amazon 合规结论 |

### 交互方式

V1 不强制接入评论插件。V2 或深挖阶段采用半自动交互：

```text
工作台生成 3-5 个核心 ASIN 采集清单
  -> 运营把 ASIN 放入评论采集插件
  -> 插件导出 Excel 评论明细
  -> 插件可选导出 HTML AI 分析报告
  -> 工具读取 Excel，生成 reviews_normalized.json
  -> 工具生成 VOC 证据账本
  -> 工具把 VOC 和卖家精灵市场/关键词/竞品数据合并
```

规则：

- Excel 是机器分析主输入。
- HTML 是人工阅读材料。
- 同时提供 HTML 时，系统可把它当“已有摘要”，但不能替代 Excel 证据链。
- 后续插件可增加标准 JSON 导出，减少 Excel 解析不确定性。

## 初始输入模型

V1 必填：

| 字段 | 说明 |
|---|---|
| `site` | 目标站点，默认 US |
| `exclusion_rules` | 明确禁区：侵权、强认证、明显低价内卷、售后风险等 |

V1 可选：

| 字段 | 说明 |
|---|---|
| `search_scope` | 大概方向，可以是大类、场景、关键词，也可以为空 |
| `preference_rules` | 偏好条件：轻小、非强季节、10 美金以上、近半年新品有机会等 |
| `supply_chain_advantages` | 供应链优势：塑料、五金、布艺、收纳、户外等 |
| `operator_hypotheses` | 运营假设：想找低退货、高复购、可差异化等方向 |
| `product_flags` | 带电、带电池、无线/蓝牙、儿童、食品接触、皮肤接触、医疗/健康宣称、激光/UV/加热/运动部件 |
| `target_price_range` | 目标售价区间 |
| `purchase_cost` | 采购价 |
| `actual_weight_g` | 实际重量，运营手填 |
| `volume_weight_g` | 体积重，运营按尺寸或经验提供 |
| `billable_weight_g` | 头程计费重，系统取实际重量和体积重较大值 |
| `first_leg_channel` | 头程渠道：美国美森/美国普船/加拿大尊享达/加拿大海卡 |
| `first_leg_shipping` | 头程费用，系统可按计费重和渠道单价估算 |
| `fba_fee` | FBA 费用，运营手填 |
| `storage_fee` | 仓储费，系统按建议售价 3% 计算 |
| `inbound_placement_fee` | 入库配置费，运营手填；不确定则待补，不默认 0 |
| `return_rate_assumption` | 退货率假设和来源 |
| `ad_rate_assumption` | 新品广告费率，默认 20% |
| `operator_notes` | 运营经验、供应链能力、图片/A+想法、CPC 经验 |

## 核心流程

### 1. 边界确认

目标：把模糊选品意图转成可执行的候选发现任务，防止市场混池、风险混池、关键词混池。

产物：

- 选品意图卡
- 候选发现任务
- 排除清单
- 待补字段清单

规则：

- 没有站点和禁区，不启动正式候选发现。
- 产品属性不足时，知产/合规只能写“待确认”。

### 2. 市场扫描

目标：判断这个市场是否值得继续看。

看：

- Top100 销量/销售额
- 价格带
- 品牌集中度
- 卖家集中度
- 新品占比
- 评论门槛
- 评分分布
- 淡旺季和趋势
- CPC 或建议竞价参考

规则：

- Top100 不完整时，不进入正式初判。
- 正式深挖报告必须完成 Top100 基础属性打标。
- 多 SKU/变体链接必须标记统计口径，避免父子体数据混算。
- CPC 来源必须标注；卖家精灵建议竞价不等于广告后台真实 CPC。

### 2.5 属性打标和交叉分析

目标：把 Top100 从商品列表变成供需结构图。

看：

- 功能标签
- 规格标签
- 外观/形态标签
- 价格带标签
- 使用场景标签
- 标签置信度
- 供给数量
- 需求证据
- 伪空白原因

规则：

- Top100 基础属性打标是正式深挖报告的必做项。
- 标签低置信度时标“待确认”，不硬猜。
- 交叉分析不能只标“空白”，必须解释原因：需求不存在、技术难、供应链难、利润不成立，还是市场忽视。

### 3. 竞品池生成

目标：让运营先确认样本是否正确。

竞品池分三组：

| 组 | 默认规则 |
|---|---|
| Top10 标杆组 | 当前类目销量/排名靠前，代表主流打法 |
| 近半年放量新品组 | 近半年上架，且 BSR 进入小类前 100，或月销量达到 Top100 月销量中位数 20% 以上 |
| 结构补充组 | 低价、高价、高评分、差评集中、不同功能路线 |

规则：

- 运营必须能删除不相关 ASIN。
- 竞品选择逻辑必须保存，不能只保存最终 ASIN 列表。

### 4. 利润参考测算

目标：早期判断利润空间，不替代运营最终核算。

| 层级 | 公式 |
|---|---|
| 基础 FBA 毛利 | 建议售价 - 采购价 - 头程 - FBA 费用 - 佣金 - 仓储费 - 入库配置费 |
| 扣广告和退货后的 FBA 毛利 | 基础 FBA 毛利 - 新品广告费 - 预估退款损失 |

默认：

- 佣金率先按 15%，实际以 Amazon 后台费率表为准。
- 新品广告费率默认 20%，运营可调整。
- FBA 费用运营手填，以亚马逊后台/收入计算器为准。
- 仓储费早期统一按建议售价 3% 简化估算。
- 入库配置费运营手填；拿不到时标记待补，不默认 0。
- 头程费用按 `计费重(g) / 1000 * 渠道单价` 估算，计费重取体积重和实际重较大值。
- 当前头程经验单价：美国美森 11 元/kg、美国普船 6 元/kg、加拿大尊享达 22 元/kg、加拿大海卡 9 元/kg；美国美森约等于加拿大尊享达，美国普船约等于加拿大海卡。
- 退货率优先用类目平均值，必须标注来源。

每层都输出毛利额和毛利率。

### 5. 退货风险初筛

目标：提醒运营早期避开明显高风险方向，但不把退货率做成自动淘汰规则。

| 情况 | 系统状态 |
|---|---|
| 细分类目退货率长期明显高于平均 | 高风险 |
| 评论反复提到业内长期难解决的结构性问题 | 结构性问题线索 |
| 有明确改品方案 | 可试做，必须写验证点 |
| 没有退货率数据 | 用类目平均值，标待复核 |

退货率来源枚举：

- 第三方工具估算值
- 运营经验值
- 自有后台数据
- 暂用类目平均值

### 6. 知产初筛

目标：早期识别不值得继续投入的风险。

| 类型 | 处理 |
|---|---|
| 外观专利 | 标相似结构、相似外观、待复核对象 |
| 实用/发明专利 | 标核心功能/结构/使用方式风险 |
| 商标 | 标禁用词、品牌词、标题词风险 |
| 版权 | 标图片、图案、IP、说明书、A+素材风险 |

规则：

- 只写“疑似/可能/待复核”，不写法律结论。
- 强专利风险未排除前，不给“继续看/立项”高置信结论。

### 7. 合规认证初筛

目标：提前预判可能需要的材料、测试、认证周期和成本。

| 产品属性 | 美国常见可能材料 | 欧盟/英国常见可能材料 | 状态 |
|---|---|---|---|
| 儿童用品/玩具 | CPSC、CPC、CPSIA、ASTM F963 | CE 玩具安全、EN71、UKCA | 强制前置 |
| 一般受 CPSC 规则约束消费品 | GCC、对应产品规则 | GPSR 或品类安全规则 | 先查标准 |
| 带电/电子产品 | FCC、UL/ETL/NRTL、能效 | CE、EMC、LVD、RoHS、UKCA | 前置复核 |
| 蓝牙/Wi-Fi/遥控/RF | FCC Certification / SDoC、FCC ID | RED、CE、UKCA | 前置复核 |
| 锂电池/含电池 | UN38.3、MSDS/SDS、UL 相关测试、运输要求 | UN38.3、RoHS、Battery Regulation | 前置复核 |
| 食品接触/厨房用品 | FDA food contact、Prop 65 | LFGB、EU food contact、REACH | 前置复核 |
| 化妆品/护肤/接触皮肤液体 | FDA 标签、MoCRA、成分和安全证明 | EU Cosmetics Regulation | 高风险 |
| 医疗/治疗/健康宣称 | FDA medical device / OTC 风险 | MDR/UK medical device 风险 | 谨慎或避开 |
| 激光/UV/辐射电子产品 | FDA CDRH radiation-emitting products | CE 及对应安全标准 | 前置复核 |
| PPE/防护用品 | NIOSH/FDA/OSHA 等视产品而定 | PPE Regulation、CE/UKCA | 高风险 |

规则：

- 缺少产品属性时，状态只能是“待确认”。
- 系统只给“可能材料”和“复核入口”，不写最终合规结论。

### 8. 机会可信度判断

每个机会必须有假设、证据、反证、风险和下一步。

| 组成 | 说明 |
|---|---|
| 机会假设 | 目标用户、使用场景、当前不满、产品方案、预期结果 |
| 需求证据 | 关键词搜索、趋势、流量词 |
| 成交证据 | Top100、竞品销量、价格带、BSR |
| 痛点证据 | 评论、QA、差评主题 |
| 供给证据 | 属性分布、竞品结构、交叉矩阵 |
| 利润证据 | 采购、FBA、广告、退货、售价 |
| 风险证据 | 商标、专利、认证、季节性、供应链、数据偏差 |
| 反证 | 空白是否没人要、销量是否异常、痛点是否小众、方案是否用户无感 |

状态：

| 状态 | 含义 |
|---|---|
| 继续看 | 市场、竞品、利润、风险暂时说得通 |
| 试做 | 有机会，但关键假设未验证 |
| 观察 | 有趋势或痛点，但证据不足或资源暂不匹配 |
| 先放弃 | 利润差、风险高、无法差异化或数据反证强 |

## 硬性规则

1. Top100 不完整，不生成正式状态卡。
2. 没有数据来源和采集时间，不写入强判断。
3. 没有竞品选择逻辑，不进入评论深挖。
4. 每个统计结论必须能追溯到 Excel Sheet、卖家精灵导出文件或 MCP 原始索引。
5. 每个机会点必须同时写“成立理由”和“不成立风险”。
6. 每个空白/薄供给必须解释原因：没人要、做不到、利润差、认证难，还是数据不足。
7. AI 不能替运营确认市场边界、供应链能力、禁区和最终状态。
8. 商标/专利检查只做初筛，不能写成法律结论。
9. 合规认证预判必须基于产品属性；缺少关键属性时，只能标“待确认”。
10. 利润结果必须同时给毛利额和毛利率，并标注“参考值”。
11. 仓储费在早期利润参考中统一按建议售价 3% 简化估算，并标注为内部估算口径。
12. 退货率必须标注来源。
13. 评论/VOC 优先使用自有评论插件导出的 Verified Purchase Excel；HTML 只作为人工阅读材料。
14. 强专利或强认证风险未排除前，不给“继续看/立项”高置信结论。

## 验收标准

### V1 通过标准

- 只输入站点、明确禁区，必要时补大概方向、偏好和供应链优势后，能生成候选品池。
- 候选品池能说明每个候选方向为什么出现、缺什么数据、是否值得继续看。
- Top100 数据完整，并完成数据质量检查。
- 正式深挖报告完成 Top100 基础属性打标、标签置信度和属性交叉分析。
- 能识别并标记多 SKU/变体统计口径，避免父子体数据混算。
- 至少完成市场结构、关键词、竞品池、退货风险、两层 FBA 毛利、知产/合规初筛。
- 竞品池包含 Top10 标杆组、近半年放量新品组、结构补充组。
- 利润参考测算给出基础 FBA 毛利、扣广告和退货后的 FBA 毛利，以及两层毛利率。
- 知产/合规卡能标出风险等级、触发原因和待复核项。
- 状态卡能给出继续看/试做/观察/先放弃，以及核心理由和下一步。
- 所有强判断可追溯到数据来源或运营手填项。
- 生成 `research_package.json`、`data.xlsx`、`report.md`、`summary.md`、`dashboard.html`。
- V1 允许通过配置文件或表格补数，不要求网页交互。

### V2 通过标准

- 能通过网页创建调研任务。
- 能在网页里补成本、调整利润参数、删除/替换竞品 ASIN。

| 手动导出字段不稳定 | 数据清洗失败或漏字段 | 先做导出清单和字段校验，缺字段时让用户补导 |
| MCP 需要额外付费 | 自动化接入延期 | V1 采用手动导出/导入闭环，后续预算允许再替换采集层 |
| Top100 混池 | 市场判断失真 | 第一步做市场边界识别，必要时拆市场 |
| 多变体 ASIN 统计失真 | 销量/评论误判 | 标记变体结构，异常 ASIN 单独备注 |
| AI 打标误判 | 交叉矩阵错误 | 引入置信度和人工确认清单 |
| 评论样本不足 | 痛点不可靠 | 标注样本量，不足时只做弱结论 |
| 数据源口径变化 | 历史记录不可比 | 每次记录工具、字段、时间、站点 |
| 工作台看起来完整但不能行动 | 运营仍然要手动重做 | 强制状态卡、待补数据卡、下一步动作 |
| 利润参考被误当最终核算 | 误判可做性 | 明确标注参考值，保留运营手填和复核 |
| 知产/合规被误当最终结论 | 法律/平台风险 | 全部写初筛、待复核、可能材料，不写最终结论 |
