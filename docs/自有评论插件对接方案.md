# 自有评论插件对接方案

更新日期：2026-06-08

## 结论

V1 最稳的对接方式是文件导入：

`候选池筛出 ASIN 批次 -> 浏览器评论插件导出 Excel + HTML AI 报告 -> 选品系统读取 Excel -> 生成 review_voc_package -> 合并到重点候选深挖`

不建议 V1 直接读取 Chrome Storage，也不建议让选品系统控制插件页面。插件继续负责浏览器登录态、慢速采集、翻译、Excel 导出和 HTML AI 报告；选品系统只接收导出文件。

## 为什么这样接

| 方案 | 结论 | 原因 |
|---|---|---|
| 读取插件 Excel | 推荐 | 字段稳定、可追溯、方便运营手动传入，也不会绑定浏览器状态 |
| 读取 HTML AI 报告 | 辅助 | 报告适合人读，但不适合作为结构化证据主来源 |
| 读取 Chrome Storage | 暂不做 | 和浏览器、扩展 ID、运行状态强绑定，稳定性差 |
| 直接改插件推送数据 | 后续再做 | 需要定义两个项目之间的协议，V1 容易变重 |

## 插件已确认导出格式

Excel：

- 文件名示例：`B07R56CBWX-multi-2026-06-07.xlsx`
- Sheet：`评论数据`
- 规则：只导出 Verified Purchase 评论
- 多 ASIN / 多站点：合并在同一个 Sheet，通过 `ASIN` 和 `站点` 区分

关键字段：

| 字段 | 用途 |
|---|---|
| ASIN、站点 | 对齐竞品池和候选方向 |
| 评论ID、评论链接 | 证据追溯 |
| 评论日期、评星、情绪 | 时间、口碑和差评结构 |
| Helpful数量、是否有买家实拍、图片数量 | 权重和证据强度参考 |
| 评论产品的属性、颜色、尺寸 | 变体和细分问题 |
| 英文标题、英文评论、标题中文翻译、评论中文翻译 | VOC 分析主文本 |

HTML AI 报告：

- 文件名示例：`B07R56CBWX-multi-2026-06-07-report.html`
- 用途：辅助阅读痛点、亮点、改品建议
- 边界：不能替代 Excel 证据；正式结论必须能回到评论 ID

## 推荐落盘位置

评论插件导出的原始文件，建议和卖家精灵导出分开存放，仍然放在项目根目录下。

推荐结构示例：

```text
/Users/sxie/Documents/亚马逊/amz-product-research-workbench/
  评论插件导出_刮窗器_20260608/
    B07....xlsx
    B07....-report.html
```

如果同一轮有多个 ASIN 或多站点评论文件，也尽量都放进这个目录，工作流直接传目录里的一组文件路径即可。

## 当前命令

```bash
python3 scripts/build_review_voc_from_plugin_export.py \
  /tmp/review_voc_hands_free_leashes \
  /Users/sxie/Downloads/B07R56CBWX-multi-2026-06-07.xlsx \
  /Users/sxie/Downloads/B07R56CBWX-multi-2026-06-07-report.html \
  --candidate-id cand-dog-running-leash \
  --candidate-name "Hands Free Leashes"
```

输出：

- `review_voc_package.json`：结构化 VOC 数据包
- `voc_report.md`：可读 VOC 报告
- `voc_summary.md`：摘要
- `voc_evidence.xlsx`：痛点、亮点、评论明细和 AI 报告参考

## 进入选品系统的规则

1. Excel 是结构化主来源。
2. HTML AI 报告只作为参考，不直接作为强证据。
3. 每个痛点和亮点必须保留评论 ID、ASIN、评分、日期、证据片段和评论链接。
4. 多 ASIN 数据优先用于品类共性痛点；单 ASIN 数据优先用于竞品短板。
5. 只有候选方向进入深挖后才接评论插件，不在候选池初筛阶段要求评论数据。
6. 评论插件的输入建议是候选池筛出的 ASIN 批次，通常先取 10-20 个，优先包含 Top10 标杆、新品和争议竞品，不是只取 3-5 个孤立样本。

## 合并到深挖报告

把 `review_voc_package` 合并进 `research_package`：

- `review_sources`：记录插件 Excel 和 HTML 来源
- `voc_analysis`：写入痛点、亮点、场景、改品机会
- `opportunity_hypotheses`：追加可追溯的 VOC 证据
- `status_card`：把评论风险纳入继续/观察/放弃判断

命令：

```bash
python3 scripts/build_research_package_from_candidate.py \
  <candidate_pool.json> \
  <research_package.json> \
  <candidate_id> \
  --voc-package <review_voc_package.json>
```

合并后，主报告和 Excel 会新增评论 VOC 摘要、痛点证据、亮点证据和改品机会。
