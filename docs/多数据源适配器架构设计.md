# 多数据源适配器架构设计

> 创建日期：2026-06-12
> 状态：设计确认中，未开始实施

## 背景与目标

当前脚本层硬耦合卖家精灵数据格式，导致：
- Sorftime MCP 数据只能由 Claude 在对话中直接读取，无法进入结构化报告
- 未来引入第三个数据平台时需要大范围修改现有脚本

**目标**：引入 Adapter 层和 Normalized Schema，让脚本核心层对数据来源透明——加新数据源只需写一个新 Adapter，核心脚本零改动。

---

## 整体架构

```
数据源层
├── 卖家精灵 CSV/XLSX        ─→ SellerSpriteAdapter ─┐
├── Sorftime MCP JSON        ─→ SorftimeAdapter       ─┤─→ NormalizedData ─→ 脚本核心层
└── [未来平台 X]              ─→ PlatformXAdapter    ─┘
```

**关键约束**：Normalized Schema 的字段名与现有 product dict 完全一致。下游脚本的 `product.get("monthly_units")` 类访问不需要任何修改，字段缺失时返回 `None`，现有 `is_blank()` / `to_float()` 逻辑自然兼容。

## 一、NormalizedProduct Schema

每个字段一行说明来源可用性（SS = 卖家精灵，SF = Sorftime）。

```python
# packages/research_core/schema/normalized_product.py

@dataclass
class NormalizedProduct:
    # ── 身份字段（两源都有）──
    asin: str
    title: str
    brand: str | None
    parent_asin: str | None           # SS: 直接；SF: 无
    category: str | None

    # ── 价格（两源都有，精度相近）──
    price: float | None

    # ── 销量信号（SS 精确，SF 为估算）──
    monthly_units: float | None       # SS: 精确；SF: 估算（较低置信度）
    monthly_revenue_usd: float | None # SS: 精确；SF: 估算

    # ── 评价（两源都有）──
    rating: float | None
    rating_count: float | None

    # ── Listing 特征 ──
    listing_days: float | None        # SS: 直接；SF: 暂无（上架日期需转换）
    fulfillment: str | None           # SS: 直接；SF: 部分有
    lqs: float | None                 # SS: 专有，SF 无此字段
    variant_count: float | None       # SS: 直接；SF: 需调 product_variations
    has_a_plus: str | None            # SS 专有
    has_video: str | None             # SS 专有
    bullet_points: str | None         # SS: 导出包含；SF: 需额外调 product_detail

    # ── 元数据（不影响下游计算逻辑）──
    _field_sources: dict[str, FieldSource] = field(default_factory=dict)
    data_freshness: str | None = None  # ISO 日期字符串

@dataclass
class FieldSource:
    source: str          # "seller_sprite" | "sorftime" | "manual"
    confidence: str      # "high" | "medium" | "low"
    note: str | None = None
```

**展开为 dict 后（供脚本使用）**：

```json
{
  "asin": "B0XXXXXX",
  "title": "...",
  "monthly_units": 1200,
  "lqs": null,
  "_field_sources": {
    "monthly_units": {"source": "seller_sprite", "confidence": "high"},
    "lqs": {"source": null, "confidence": null, "note": "仅卖家精灵提供，本次未导入"}
  }
}
```

## 二、NormalizedKeyword Schema

```python
@dataclass
class NormalizedKeyword:
    keyword: str

    # 两源都有
    monthly_search_volume: int | None
    weekly_search_volume: int | None

    # Sorftime 独有
    cpc: float | None
    trend_direction: str | None       # "增长" | "衰退" | "均衡" | "季节性"
    trend_24m: list[dict] | None      # [{month, search_volume}, ...]
    seasonality: str | None
    competitor_count: int | None      # 首页竞品数

    # 卖家精灵 ABA 独有
    aba_rank: int | None              # ABA 搜索频率排名
    click_share_top1: float | None    # Top1 点击份额

    _field_sources: dict[str, FieldSource] = field(default_factory=dict)
```

## 四、Adapter 接口

```python
# packages/research_core/adapters/base_adapter.py

class BaseDataAdapter:
    """所有数据源 Adapter 的基类。实现三个方法即可接入系统。"""

    source_type: ClassVar[str]  # 注册标识，如 "seller_sprite" / "sorftime"

    def fetch_products(self) -> list[NormalizedProduct]:
        """返回规范化产品列表。无数据时返回空列表，不抛异常。"""
        return []

    def fetch_keywords(self) -> list[NormalizedKeyword]:
        """返回规范化关键词列表。"""
        return []

    def fetch_category(self) -> NormalizedCategory | None:
        """返回规范化类目数据，无数据时返回 None。"""
        return None
```

**注册方式**（新增数据源只需两步）：

```python
# packages/research_core/adapters/__init__.py

ADAPTER_REGISTRY: dict[str, type[BaseDataAdapter]] = {
    "seller_sprite": SellerSpriteAdapter,
    "sorftime":      SorftimeAdapter,
    # "platform_x": PlatformXAdapter,  ← 未来加一行
}
```

## 五、Manifest v2 Schema

在现有 manifest 结构上**向后兼容扩展**（不破坏 v1 格式）：

```json
{
  "metadata": {
    "manifest_version": 2,
    "manifest_id": "manifest-xxx",
    "task_name": "...",
    "site": "US",
    "generated_at": "2026-06-12T00:00:00Z"
  },
  "files": [
    {
      "file_id": "file_001",
      "source_type": "seller_sprite_search_results",
      ...
    }
  ],
  "sorftime_snapshot": {
    "fetched_at": "2026-06-12T10:30:00Z",
    "category_trend": { ... },
    "keyword_data": [ ... ],
    "product_list": [ ... ]
  },
  "data_quality": { ... }
}
```

`sorftime_snapshot` 字段缺失时，系统按 v1 逻辑运行，完全向后兼容。

## 六、字段合并策略

两源都有数据时的优先规则：

```python
# packages/research_core/adapters/merge_strategy.py

FIELD_PRIORITY: dict[str, str] = {
    # 卖家精灵优先（精度更高）
    "monthly_units":        "seller_sprite",
    "monthly_revenue_usd":  "seller_sprite",
    "lqs":                  "seller_sprite",
    "listing_days":         "seller_sprite",
    "has_a_plus":           "seller_sprite",
    "has_video":            "seller_sprite",
    "bullet_points":        "seller_sprite",
    "parent_asin":          "seller_sprite",

    # Sorftime 优先（实时/独有）
    "cpc":                  "sorftime",
    "trend_direction":      "sorftime",
    "trend_24m":            "sorftime",
    "seasonality":          "sorftime",
    "competitor_count":     "sorftime",

    # 任意源都可（取第一个有效值）
    "price":                "any",
    "rating":               "any",
    "rating_count":         "any",
    "brand":                "any",
    "category":             "any",
    "fulfillment":          "any",
    "variant_count":        "any",
}
```

合并逻辑：对每个字段，按 `FIELD_PRIORITY` 取优先源的值；若优先源无此字段，fallback 到另一源；都无则为 `None`。

## 七、现有文件变更清单

### 需要修改（最小改动）

| 文件 | 改动内容 |
|---|---|
| `scripts/inspect_manual_exports.py` | 新增 `--sorftime-snapshot <json>` 参数，将 Sorftime 快照写入 manifest v2 的 `sorftime_snapshot` 字段 |
| `scripts/build_candidate_pool_from_import_manifest.py` | 读取 manifest 后调用适配器层，而非直接解析卖家精灵格式；核心分析逻辑不动 |
| `packages/research_core/rules/market_structure_rules.py` | 极小改动：`tag_notes()` 补一条 Sorftime 专有字段的注释说明（其余已能处理 None） |

- `scripts/build_research_package_from_candidate.py` — 吃 `candidate_pool.json`，格式不变
- `scripts/apply_sorftime_verification.py` — 独立流程，不受影响
- `packages/report_renderer/render_report.py` — 吃 `research_package.json`，不变
- 所有 VOC 相关脚本 — 不受影响

## 八、推荐实施顺序

```
阶段一：Schema + SellerSpriteAdapter（稳定现有功能）
  1. 定义 NormalizedProduct / NormalizedKeyword / NormalizedCategory
  2. 将 inspect_manual_exports.py 中的卖家精灵解析逻辑抽取到 SellerSpriteAdapter
  3. 更新 build_candidate_pool_from_import_manifest.py 通过 Adapter 层读取数据
  4. 端到端验证：新路径产出与旧路径完全一致

阶段二：SorftimeAdapter + Manifest v2
  5. 实现 SorftimeAdapter（将 MCP 返回的 JSON 转为 NormalizedProduct 等）
  6. inspect_manual_exports.py 支持 --sorftime-snapshot 参数
  7. 实现 merge_strategy.py 合并逻辑

阶段三：端到端验证
  8. 仅卖家精灵输入：报告与之前完全一致（回归验证）
  9. 仅 Sorftime 输入：能生成轻量报告（部分字段为 null，报告标注来源限制）
  10. 双源输入：字段按合并策略取优先值，报告质量最优
```

## 九、遗留问题 / 需确认

1. **Sorftime 产品列表精度**：`product_search` 返回的月销量是估算值还是精确值？这决定 `monthly_units` 的 `confidence` 标注。
2. **仅 Sorftime 模式的报告降级**：`lqs`、`has_a_plus`、`has_video`、`bullet_points` 缺失时，11 维度打标签会有 4 个维度输出"未知"，报告中需要明确标注数据来源限制，而不是让运营误以为是完整分析。
3. **SorftimeAdapter 的触发方式**：Sorftime MCP 是由 Claude 在对话中调用的，调用结果需要被保存为 JSON 文件（`sorftime_snapshot.json`），再由 `inspect_manual_exports.py` 读入 manifest。这个 JSON 的保存步骤需要在 Skill 中明确指导运营（或 Claude 自己保存）。
