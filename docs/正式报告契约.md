# 正式报告契约

Stage 7 采用三段式交付：脚本生成 `report_data.seed.json`，Report Generation Agent 增强为 `report_data.json` 并手写 HTML，脚本再生成 XLSX 和 QA。运营只看 HTML / XLSX；后台文件用于溯源和质量门禁。

## 最终交付物

| 文件 | 生成方式 | 用途 |
|---|---|---|
| `analysis/report_data.seed.json` | 脚本 `build_analysis_report.py` | 报告数据草稿，只作为 Agent 增强输入 |
| `analysis/report_data.json` | Report Generation Agent | HTML 和 XLSX 的统一数据底座，保留 `source_path` |
| `analysis/<中文品名>_分析报告.html` | Report Generation Agent 手写 | 运营阅读的决策建议书 |
| `analysis/<中文品名>_决策工具包.xlsx` | 脚本 `build_analysis_report.py` | 运营决策工具包，5 Sheet（路线计分卡、竞品拆解、关键词矩阵、样品检查表、冷启动预算） |
| `analysis/delivery_qa_result.json` | 脚本 `build_analysis_report.py` | 交付质量门禁 |

## 生成职责

| 环节 | 负责方 | 输入 | 输出 | 限制 |
|---|---|---|---|---|
| Seed | 脚本 | `analysis_packet.json`、Evidence Packet、Integrated Judgment | `report_data.seed.json` | 只生成草稿，不冒充正式 `report_data.json` |
| 报告增强 | Report Generation Agent | `report_data.seed.json`、Integrated Judgment | `report_data.json`、HTML | 不得新增证据包外数字 |
| 决策工具包与 QA | 脚本 | `report_data.json`、`integrated_operator_judgment.json`、证据包 | XLSX（5 Sheet）、`delivery_qa_result.json` | 不负责手写正式 HTML |

## HTML 报告板块

| 板块 | 内容 | 写作要求 |
|---|---|---|
| Hero | 一句话结论 + 关键指标 | 直接给运营判断，不写工具过程 |
| 市场全貌 | 体量、季节性、新品信号、风险 | 先给判断再给数据，不堆原始数字 |
| 核心竞品 | ASIN 对比表和路线判断 | 每条路线至少 2 个代表 ASIN，关键判断给判断不是描述 |
| 用户痛点 → 产品规格 | P0/P1/P2 痛点和规格建议 | 直接指导打样 |
| 价格带分布 | 可视化价格带 + 竞品参考价 | 不拍板定价，只给分布和验证建议 |
| 关键词与流量策略 | 主攻意图词、可测词、明确否定词 | 每条配策略说明，不只列数字 |
| 风险与下一步 | 风险/优势、Go/No-Go 条件、下一步动作 | 条件表含具体阈值和当前状态 |

HTML 不固定展示“数据来源与口径”板块；如需说明边界，只能以“样本边界 / 判断口径”自然写入业务板块。HTML 不暴露 MCP、Agent、tool、packet、source_path、冲突复核过程或内部数据来源分歧。

## XLSX 10 个 Sheet

| Sheet | 内容 |
|---|---|
| Summary | 核心指标和结论摘要 |
| Source Packets | 后台证据包来源和状态 |
| Category Derivation | 品类推导步骤和证据 |
| Category Candidates | 候选类目和角色 |
| Reference ASINs | 参考 ASIN 池 |
| Market Opportunity | 价格带机会和新品信号 |
| Keyword Pool | 关键词池和角色分层 |
| VOC | 痛点到规格映射 |
| Route Judgment | 路线综合判断 |
| Risks And Next | 风险和下一步动作 |

## 质量门槛

| 门槛 | 规则 |
|---|---|
| Hero 要有明确结论 | 建议进入小批量验证 / 建议补齐数据后再评估 / 建议暂停推进，不能含糊 |
| 先判断后数据 | 每个板块先给运营判断，再用数据支撑 |
| 事实推断分开 | 价格、销量、评分是事实；定价建议、毛利阈值、差异点价值是推断 |
| 用词克制 | 不写“护城河”“几乎零竞争”“不需要试错” |
| VOC 要能追溯 | 痛点必须能回到评论 ID、ASIN、评分、原文片段 |
| 禁止内部术语 | HTML 中不出现 Agent、MCP、tool、spawn、packet、pipeline、source_path |
| 不强结论 | 证据不足时只能写建议补数据，不能强行给进入建议 |
| 阻塞项不得忽略 | blocking conflict、data_quality blocked、低置信强结论、schema_version 不一致、progress 未完成都会阻断交付 |

## 校验入口

Stage 7 交付后必须运行：

```bash
python3 -m packages.research_core.pipeline.build_analysis_report <run_dir>
```

QA 检查项：

- HTML / XLSX / `report_data.json` 存在。
- `report_data.json` 的 `source_path` 可追溯到证据包。
- 证据包结构完整，`schema_version` 一致。
- HTML 不含旧模板标记、内部工具术语、Agent/MCP 过程或冲突复核过程。
- P0 阻塞规则全部通过。
