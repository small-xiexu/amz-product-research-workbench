# 正式报告契约

Stage 7 最终交付物定义和质量门槛。当前模型：AI 手写 HTML + 脚本生成 XLSX，`run_id` 格式 `YYYYMMDD_中文品类方向`。

## 最终交付物

| 文件 | 生成方式 | 用途 |
|---|---|---|
| `analysis/<中文品名>_分析报告.html` | **AI 以资深运营专家视角手写** | 运营阅读的决策建议书，8 个板块 |
| `analysis/<中文品名>_数据回表.xlsx` | **脚本 `build_analysis_report.py` 生成** | 数据回表，10 个 Sheet，给数字溯源 |

中间产物（`report_data.json`、`delivery_qa_result.json`）由脚本生成，不要求运营 review。

## HTML 报告 8 板块

| 板块 | 内容 | 写作要求 |
|---|---|---|
| Hero | 一句话结论 + 5 个关键指标（细分 TAM、大类 TAM、均价、竞品数、VOC 覆盖） | 细分 TAM 和大类 TAM 必须分开 |
| 市场全貌 | 2 列洞察卡片（体量、季节性、新品信号、风险） | 先给判断再给数据，不堆原始数字 |
| 数据来源与口径 | 采样日期、工具、样本筛选逻辑、事实 vs 推断 | 让报告经得起复盘 |
| 核心竞品 | ASIN 对比表（ASIN、品牌、月销、价格、评论、评分、上架时间、路线、关键判断） | 每条路线至少 2 个代表 ASIN，关键判断给判断不是描述 |
| 用户痛点 → 产品规格 | P0/P1/P2 优先级排序，每个痛点写"竞品问题"和"你的产品应该做到" | 全报告最强部分，直接指导打样 |
| 价格带分布 | 可视化价格带 + 竞品参考价 | 不给拍板定价建议，只给分布 |
| 关键词与流量策略 | 按意图分三类：主攻意图词、可测词、明确否定词 | 每条配策略说明，不只列数字 |
| 风险与下一步 | 风险/优势双栏 + Go/No-Go 决策条件表 + 下一步 3 件事 | 条件表含具体阈值和当前状态 |

## XLSX 10 个 Sheet

| Sheet | 内容 |
|---|---|
| Summary | 核心指标和结论摘要 |
| Source Packets | 证据包来源和状态 |
| Category Derivation | 品类推导步骤和证据 |
| Category Candidates | 候选类目和角色 |
| Reference ASINs | 参考 ASIN 池 |
| Market Opportunity | 价格带机会和新品信号 |
| Keyword Pool | 关键词池和角色分层 |
| VOC | 痛点到规格映射 |
| Route Judgment | 路线综合判断 |
| Risks And Next | 风险和下一步动作 |

## 质量门槛

| 门槛 | 规则 |
|---|---|
| Hero 要有明确结论 | 建议进入小批量验证 / 建议补齐数据后再评估 / 建议暂停推进，不能含糊 |
| 先判断后数据 | 每个板块先给运营判断，再用数据支撑，不是先列数据让运营猜 |
| 事实推断分开 | 价格、销量、评分是事实；定价建议、毛利阈值、差异点价值是推断 |
| 用词克制 | 不写"护城河""几乎零竞争""不需要试错"；写"直接竞品少""短期竞争压力低" |
| VOC 要能追溯 | 痛点必须能回到评论 ID、ASIN、评分、原文片段 |
| 禁止内部术语 | HTML 中不出现 Agent、MCP、tool、spawn、packet、pipeline 等术语 |
| 不强结论 | 证据不足时只能写建议补数据，不能强行给进入建议 |

## 校验入口

Stage 7 交付后必须运行：

```bash
python3 -m packages.research_core.pipeline.build_analysis_report <run_dir>
```

脚本会生成 XLSX + JSON + QA 结果。QA 检查项：
- `<中文品名>_分析报告.html` 存在（AI 手写）
- `<中文品名>_数据回表.xlsx` 存在（脚本生成）
- 证据包结构完整
- HTML 不含已移除的旧模板标记

详细 QA 规则见 `skills/amazon-product-research/agents/delivery-qa-agent.md`。
