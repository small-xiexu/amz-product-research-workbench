# 选品分析模式库

本文档用于约束 Claude 在市场扫描、候选深挖和评论 VOC 分析中的洞察写法。脚本只负责结构化、计算和校验；真正的判断必须使用下面的分析模式，把事实、推断、风险和验证动作分开。

## 使用原则

- 每个正式深挖报告至少使用 3 种分析模式，优先覆盖市场结构、属性交叉、VOC、利润/合规待补和 Go/Wait/No-Go。
- 每个强判断必须能回溯到 `candidate_pool.json`、`research_package.json`、`review_voc_package.json`、人工模板或 Sorftime 返回。
- 模式不是套话。没有对应证据时，不写该模式，改写成待补或验证动作。
- 同一段落中先写事实，再写推断，最后写动作；不要把“可能机会”写成已经验证的结论。

## 模式一：数据 -> 空白 -> 机会

适用场景：市场结构、价格带、评论门槛、新品表现、竞品覆盖出现明显缺口时。

证据来源：
- `market_analysis`
- `market_structure.attribute_distributions`
- `market_structure.cross_analysis`
- `competitor_pool`
- Sorftime 类目趋势或关键词趋势

输出结构：
- 数据：当前市场里哪一段供给/销量/价格/评分更突出。
- 空白：哪些组合供给薄、表现弱、或竞品没有讲清。
- 机会：这个空白是否可能变成产品切入口。
- 验证：下一步要用评论、供应链、样品或利润表验证什么。

推荐句式：
- “事实：`[字段/Sheet]` 显示 `[数据]`。推断：这说明 `[空白或结构]`。动作：先验证 `[具体动作]`，未验证前只作为 Wait 机会。”

禁止：
- 只看到某价格带商品少，就直接写“蓝海”。
- 没有 VOC 或供应链证据时，把空白写成确定需求。

## 模式二：痛点 -> 能力/供应链 -> 产品方案

适用场景：评论 VOC 已接入，需要把差评痛点转成改品方向。

证据来源：
- `review_voc_package.normalized_reviews`
- `voc_analysis.pain_points`
- `normalized_tables.voc_evidence`
- 供应链能力或运营偏好

输出结构：
- 痛点：具体痛点是什么，出现在哪些 ASIN/评分/评论中。
- 能力：我们是否有材料、结构、工艺、包装、品控或 Listing 表达能力去解决。
- 产品方案：给供应商可执行的规格、测试或打样要求。
- 风险：如果解决不了，是否会导致退货、差评或误购。

推荐句式：
- “事实：`[review_id/ASIN/评分]` 反复提到 `[痛点]`。推断：这是 `[结构性/个别品控]` 问题。方案：供应商需验证 `[具体方案]`。”

禁止：
- 把评论里一句抱怨放大成全市场痛点。
- 只写“提升质量”“优化体验”这类不可执行建议。

## 模式三：交叉维度 -> 结构性空白

适用场景：Top100 属性打标和交叉分析已经生成，需要找产品路线、价格、销量、评论门槛之间的组合机会。

证据来源：
- `Top商品打标`
- `属性分布`
- `属性交叉分析`
- `Top100原始明细`

输出结构：
- 交叉维度：说明用了哪两个或三个维度。
- 结构发现：哪个组合销量高、评论门槛低、供给薄或价格更友好。
- 机会判断：是真机会、伪机会还是待验证。
- 待确认标签：低置信度或标题无法判断的标签必须列为待确认。

推荐句式：
- “事实：`[维度A] x [维度B]` 中 `[组合]` 的 `[销量/价格/评分]` 更突出。推断：这里可能存在 `[结构性空白]`。但 `[低置信度/样本数不足]`，下一步需要 `[验证动作]`。”

禁止：
- 只罗列分布，不解释为什么影响进入策略。
- 忽略低置信度标签和多变体重复口径。

## 模式四：多维评分 -> 优先级矩阵

适用场景：需要输出 Go / Wait / No-Go、候选方向排序或竞品优先级。

证据来源：
- `decision_review.go_nogo_scorecard`
- `status_card`
- `risk_matrix`
- 利润复核模板
- 知产/合规复核模板

输出结构：
- 维度：市场规模、竞争格局、需求清晰度、新品友好度、利润可行性、风险、数据完整度。
- 权重：说明哪个维度当前最影响决策。
- 结论：Go / Wait / No-Go 必须和待补状态一致。
- 限制：利润或合规未回填时，只能给 Wait/观察/待补，不给强 Go。

推荐句式：
- “当前不是强 Go，而是 Wait：市场和 VOC 证据支持继续看，但利润、合规仍未回填，评分卡中 `[维度]` 仍是 `[状态]`。”

禁止：
- 利润和合规缺失时给强 Go。
- 得分没有字段依据。

## 模式五：待补项 -> 验证动作

适用场景：报告中出现待补字段、低质量数据、人工复核项、供应链未知项。

证据来源：
- `decision_review.missing_inputs`
- `workflow_summary.json`
- `market_structure.data_quality`
- 利润模板和知产/合规模板

输出结构：
- 待补项：缺哪个字段或证据。
- 影响：缺失会影响什么判断。
- 验证动作：谁来做、用什么资料、输出到哪里。
- 复跑入口：补齐后运行哪个脚本或校验器。

推荐句式：
- “待补：`[字段]`。影响：无法判断 `[利润/合规/需求/风险]`。动作：运营补 `[模板/证据]` 后，重新运行 `[脚本]` 并用 `validate_research_outputs.py` 校验。”

禁止：
- 写“后续再看”但不说明下一步怎么做。
- 把未验证事项在状态卡里当成已解决。

## 模式六：竞品角色 -> VOC 覆盖 -> 证据链

适用场景：解释为什么选这些 ASIN 做竞品对比和评论抓取。

证据来源：
- `candidate_pool.next_review_voc_asins`
- `competitor_pool`
- `review_voc_package.summary.asins`
- `VOC证据`

输出结构：
- 竞品角色：量级标杆、新品、功能差异、价格带、痛点参考。
- 覆盖检查：评论样本是否覆盖这些角色。
- 证据链：每个痛点是否能追到 review_id、ASIN、评分、原文片段。
- 缺口：未覆盖的角色必须列为下一轮评论抓取建议。

推荐句式：
- “本轮 VOC 覆盖了 `[角色/ASIN]`，但 `[角色]` 仍缺评论证据；因此 `[痛点/机会]` 只能作为弱结论。”

禁止：
- 只抓一个爆款 ASIN 就代表整个候选方向。
- VOC 痛点没有 review_id 和原文片段。

## 正式报告落点

| 报告章节 | 推荐模式 |
|---|---|
| 市场结构与数据质量 | 模式一、模式五 |
| 产品属性分布与交叉分析 | 模式三、模式五 |
| 竞品池与竞品选择逻辑 | 模式六 |
| 评论 VOC 与真实痛点 | 模式二、模式六 |
| 利润复核 | 模式四、模式五 |
| 知产/合规/退货风险 | 模式四、模式五 |
| Go/Wait/No-Go 决策检查 | 模式四、模式五 |

## 自检清单

- 是否至少用了 3 种模式？
- 每个强判断是否有字段、Sheet、review_id 或模板证据？
- 是否明确区分事实、推断、风险和动作？
- 利润/合规未回填时，是否避免强 Go？
- 待补项是否都变成了具体验证动作？
