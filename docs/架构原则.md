# 架构原则

更新日期：2026-06-11

## 核心规则

**脚本做计算，Claude 做解读。**

脚本产出数字、字段、结构；Claude 产出判断、建议、推断。

---

## 三层架构

```
Scripts（计算层）
    ↓ 输出结构化 JSON
Skills（行为规范层）
    ↓ 约束 Claude 的角色、流程、输出格式
Claude（分析层）
    ↓ 基于数据给出判断、建议、推断
```

### Scripts — 脚本层

**职责**：数据的搬运、转换和计算。

可以做：
- 字段提取与格式转换
- 数值计算（均值、占比、评分合计）
- 聚合统计（Top10 份额、新品占比、月销量分布）
- 数据完整性校验
- 数值评分（如 Go/No-Go 各维度的分值）

不可以做：
- 分级文字（"壁垒高/中/低"的解释句）
- 建议文字（"下一步应当……"）
- 解读文字（"这意味着市场较为分散……"）
- 机会点生成（"改品方向：……"）
- 风险结论文字

**判断方法**：函数返回值是数字/布尔/枚举 → 合法。返回值是中文解释句 → 移出脚本。

---

### Skills — 行为规范层

**职责**：告诉 Claude 在某类任务里「扮演什么角色、按什么流程走、遵守什么约束、产出什么格式」。

Skills 只包含：
- Claude 的角色与视角定位
- 任务的工作流步骤（调用哪些脚本、顺序是什么）
- 数据诚信约束（见下方模板）
- 输出格式规范

Skills 不包含：
- 私有脚本（脚本统一在 `scripts/` 下共享）
- 分析逻辑本身（那是 Claude 在对话里做的事）
- 工具调用细节（放参考文档，Skill 引用）

**组织原则**：按独立可触发的工作流单元划分，不按数据源划分。

当前 Skills：

| Skill | 触发场景 | 数据入口 |
|---|---|---|
| `market-scan` | 找方向、扫类目、看 Top100、构建候选池 | 卖家精灵导出 / Sorftime MCP |
| `review-voc-analysis` | 评论分析、VOC、痛点挖掘 | `review_voc_package.json` |
| `candidate-deep-dive` | 深挖报告、Go/No-Go、差异化建议 | `candidate_pool.json` |

---

### Claude — 分析层

**职责**：在 Skill 约束下，基于脚本产出的结构化数据，给出判断、建议、推断。

Claude 负责：
- "这个市场值不值得进"
- "壁垒高不高，有没有机会"
- 五维评分之上的 Go/No-Go 建议
- 风险的优先级判断
- VOC 维度的改品机会解读
- 所有解释性文字和行动建议

---

## 数据诚信规则（所有 Skills 通用）

1. **数据不足标注，不编造**：无法获取的字段标注「⚠️ 未能获取」，不猜测
2. **强判断必须可回溯**：所有"建议/风险/Go/No-Go"必须能指向具体来源（脚本输出文件名、MCP 工具名、人工输入字段）
3. **区分事实与推断**：用"数据显示…"表达事实，用"推断…"或"基于…判断"表达推断
4. **标注数据时效**：卖家精灵数据需标注导出日期，Sorftime 数据需标注调用时间
