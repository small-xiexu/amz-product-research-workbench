# 架构原则

更新日期：2026-06-13

## 核心规则

**脚本做计算，Claude 做解读。**

脚本产出数字、字段、结构；Claude 产出判断、建议、推断。

---

## 五层技术架构

```
CLI / Scripts（入口层）
    ↓ 调用
Workflow（应用编排层）
    ↓ 校验与交付
Contracts + Core（契约与规则层）
    ↓ 输出结构化 JSON / Excel / HTML
Renderer（报告输出层）
    ↓ 供 Claude 与运营阅读
Skills（行为规范层）
    ↓ 约束 Claude 的角色、流程、输出格式
Claude（分析层）
    ↓ 基于数据给出判断、建议、推断
```

### CLI / Scripts — 入口层

**职责**：命令行入口、兼容工具入口、参数解析。

可以做：
- 解析 CLI 参数
- 展开本地路径
- 调用 Workflow API
- 打印输出路径和简短运行结果

不可以做：
- 复制完整业务流程
- 写大量业务编排逻辑
- 绕过 Workflow 直接拼完整报告

当前主入口：`scripts/run_research_workflow.py`。它只调用 `packages.research_core.workflows.run_research_workflow()`。

### Workflow — 应用编排层

**职责**：维护交互式流程状态，或在数据齐全后批量重跑报告；不直接做复杂业务判断。

可以做：
- 维护 `workflow_state`、`decision_log`、`next_action_card`
- 判断当前阶段是否需要运营决策
- 给出下一步动作类型：调 MCP、让运营导出、导入评论、生成报告
- 调用导入盘点、候选池、VOC 和报告渲染
- 管理输出目录和固定文件名
- 生成 `workflow_summary`
- 在关键节点调用 Contracts 校验

不可以做：
- 写选品建议、改品建议、强 Go/No-Go 解释
- 把 Claude 分析逻辑写成脚本规则

当前位置：`packages/research_core/workflows/`。

当前两条 Workflow：

| Workflow | 定位 |
|---|---|
| `interactive_workflow` | 主产品体验：AI 和运营一步步协作，最终报告沉淀过程 |
| `product_research_workflow` | 批量回归/重跑工具：数据齐全后一次性生成报告四件套 |

### Contracts + Core — 契约与规则层

**职责**：数据结构、字段合并、纯计算规则、流程内结构校验。

可以做：
- 字段提取与格式转换
- 数值计算（均值、占比、评分合计）
- 聚合统计（Top10 份额、新品占比、月销量分布）
- 数据完整性校验
- 数值评分（如 Go/No-Go 各维度的分值）
- Adapter 统一不同数据源字段
- 校验核心数据包是否具备下游必需结构

不可以做：
- 分级文字（"壁垒高/中/低"的解释句）
- 建议文字（"下一步应当……"）
- 解读文字（"这意味着市场较为分散……"）
- 机会点生成（"改品方向：……"）
- 风险结论文字

**判断方法**：函数返回值是数字/布尔/枚举 → 合法。返回值是中文解释句 → 移出脚本。

当前位置：
- `packages/research_core/contracts/`
- `packages/research_core/adapters/`
- `packages/research_core/schema/`
- `packages/research_core/rules/`

### Renderer — 报告输出层

**职责**：把结构化数据包渲染成 Markdown、HTML 看板、Excel 数据底表。

可以做：
- 固定章节输出
- 表格行构建
- HTML 看板布局
- Excel Sheet 生成
- 数据来源和证据链展示

不可以做：
- 补不存在的数据
- 绕过待补状态给强结论
- 生成无法回溯的分析建议

当前位置：`packages/report_renderer/`。已按职责拆分，`render_report.py` 仅为薄门面（向后兼容 re-export）：

| 模块 | 职责 |
|---|---|
| `render_report.py` | 薄门面：`build_outputs` 编排 + 对外 re-export |
| `constants.py` | 报告共享常量（章节标题、Excel Sheet 映射） |
| `formatting.py` | 无状态格式化工具（金额/数字/币种/百分比） |
| `markdown.py` | Markdown 正式报告（12 章 builder） |
| `dashboard/style.py` | 看板 CSS 常量 |
| `dashboard/sections.py` | 看板分区渲染 |
| `workbook.py` | Excel 数据底表（`_*_rows`） |
| `render_candidate_pool.py` | 候选池预审渲染（独立链路） |
| `xlsx_writer.py` | 底层 Excel 写入 |

依赖方向单向无环：`markdown` / `dashboard` / `workbook` 三层互不依赖，统一向下依赖 `formatting` + `constants`。新增/修改某类输出时只改对应模块，不应回到门面堆逻辑。

---

### Skills — 行为规范层

**职责**：告诉 Claude 在某类任务里「扮演什么角色、按什么流程走、遵守什么约束、产出什么格式」。

Skills 只包含：
- Claude 的角色与视角定位
- 任务的工作流步骤（调用哪些脚本、顺序是什么）
- 数据诚信约束
- 输出格式规范

Skills 不包含：
- 私有脚本（脚本统一在 `scripts/` 下共享）
- 分析逻辑本身（那是 Claude 在对话里做的事）
- 工具调用细节（放参考文档，Skill 引用）

**组织原则**：按独立可触发的工作流单元划分，不按数据源划分。

当前 Skills（已收敛为单一主入口）：

| Skill | 触发场景 | 数据入口 |
|---|---|---|
| `amazon-product-research` | 全流程：从方向探索、类目扫描、候选池构建、深挖分析、VOC 评论到市场机会报告 | 卖家精灵导出 / Sorftime MCP / 评论插件 |

旧版独立 Skill（`market-scan`、`candidate-deep-dive`、`review-voc-analysis`）已于 2026-06-21 废弃并删除，功能已全部整合进 `amazon-product-research`。

---

### Claude — 分析层

**职责**：在 Skill 约束下，基于脚本产出的结构化数据，给出判断、建议、推断。

Claude 负责：
- "这个市场值不值得进"
- "壁垒高不高，有没有机会"
- 五维评分之上的 Go/No-Go 建议
- 风险的优先级判断
- VOC 维度的改品机会解读
- 所有解释性文字和行动建议

---

## 数据诚信规则（所有 Skills 通用）

1. **数据不足标注，不编造**：无法获取的字段标注「⚠️ 未能获取」，不猜测
2. **强判断必须可回溯**：所有"建议/风险/Go/No-Go"必须能指向具体来源（脚本输出文件名、MCP 工具名、人工输入字段）
3. **区分事实与推断**：用"数据显示…"表达事实，用"推断…"或"基于…判断"表达推断
4. **标注数据时效**：卖家精灵数据需标注导出日期，Sorftime 数据需标注调用时间
