# 亚马逊运营选品自查工具流程方案

更新日期：2026-06-07

## 一句话说明

这是一套选品工具。入口是模糊选品意图，系统先发现候选品池，再对重点候选做自查、补数、报告和看板。主报告尽量短，所有结论都要能追溯到来源。

它把一个选品意图拆成可复核的候选品池和任务卡：

`选品意图 -> 候选市场/关键词发现 -> 候选品池 -> 市场扫描 -> 竞品池 -> 用户痛点 -> 利润参考 -> 退货风险 -> 知产/合规初筛 -> 下一步状态`

运营使用它的目的不是“让 AI 告诉我做什么”，而是更快判断：

- 这个方向是否值得继续看
- 还缺哪些关键数据
- 哪些风险需要提前避开
- 下一步是继续看、试做、观察，还是先放弃

## 角色边界

| 角色 | 负责什么 | 不负责什么 |
|---|---|---|
| 运营 | 提供选品边界、禁区、偏好、供应链能力，复核候选品和最终业务判断 | 不需要先知道具体产品，也不需要手工整理所有数据 |
| 系统 | 拉数据、发现候选品、做初筛、生成任务卡、标待补项、保留证据链 | 不替运营做最终选品决定 |
| 律师/代理机构 | 专利、商标、侵权专业判断 | 不参与日常初筛 |
| 检测机构/平台合规 | 认证、检测、合规最终结论 | 不参与早期市场判断 |

知产和合规在工具里只做早期筛查，不能写成法律结论或认证结论，但可以写成老板能看懂的风险提示和待复核项。

## 双层输出

| 层级 | 给谁看 | 产物 |
|---|---|---|
| 底层 | 运营 | 选品意图、候选品池、任务卡、竞品池、利润参考、退货风险、知产/合规、待补数据 |
| 上层 | 摘要和看板 | Executive Summary、HTML 看板、简化结论、机会排序 |

同一份数据底座，既能复核，也能直接生成主报告和摘要。摘要尽量控制在一页内。

## V1 工作台模块

V1 先做轻量工作台，让运营能快速完成初筛。

| 模块 | 看到什么 | 需要做什么 |
|---|---|---|
| 选品意图卡 | 站点、大概方向、禁区、偏好、供应链优势 | 补充边界和禁区 |
| 候选品池卡 | 系统发现的候选市场、关键词、产品方向 | 删除不相关候选，选择重点候选 |
| 候选品任务卡 | 重点候选的关键词、产品形态、禁区、可选属性勾选 | 补充候选品边界 |
| 市场扫描卡 | Top100、价格带、品牌集中度、新品占比、评论门槛、趋势 | 判断市场是否值得看 |
| 竞品池卡 | Top10 标杆组、近半年放量新品组、结构补充组 | 删除不相关 ASIN，补充关键竞品 |
| 利润参考卡 | 两层 FBA 毛利、毛利率、待补成本项 | 补采购价、头程、仓储费、入库配置费 |
| 退货风险卡 | 类目退货率、来源、结构性问题线索 | 判断是否只是风险，还是明显不适合 |
| 知产/合规卡 | 外观/实用/发明、商标、版权、认证可能材料、待复核项 | 判断是否需要先暂停或补查 |
| 待补数据卡 | 缺失字段、弱证据、人工经验项 | 补充经验或标记后续再看 |
| 状态卡 | 继续看/试做/观察/先放弃，核心理由，下一步动作 | 修改状态，记录自己的判断 |
| 报告摘要卡 | Executive Summary、关键结论、行动建议 | 生成统一摘要 |
| 看板卡 | 机会排序、市场结构、风险提示、简化图表 | 生成统一看板 |

Excel 数据表作为底层证据源和复核底表，MD 报告和 HTML 看板作为上层阅读界面。

## 初始输入

第一步只要求选品边界，不要求运营先知道具体产品：

| 输入 | 是否必填 | 示例 |
|---|---|---|
| 目标站点 | 必填 | US |
| 大概方向 | 可选 | 户外、家居、宠物，也可以为空 |
| 明确禁区 | 必填 | 儿童、医疗、强认证、侵权、明显低价内卷等 |
| 偏好条件 | 可选 | 轻小、非强季节、10 美金以上、近半年新品有机会 |
| 供应链优势 | 可选 | 塑料、五金、布艺、收纳、户外 |

可选快速勾选项：

- 带电
- 带电池
- 带无线/蓝牙
- 儿童用品
- 食品接触
- 皮肤接触
- 医疗/健康宣称
- 激光/UV/加热/运动部件

候选品进入继续看/试做后再补的信息：

- 目标售价区间
- 供应链报价或采购价
- 预估头程费用
- FBA 费用
- 仓储费估算
- 入库配置费
- 淡旺季经验
- CPC 或 ACOS 经验
- 退货率经验
- 图片/A+想法
- 材质、涂层、认证细节

价格带只做分组和提醒，不做硬排除。报告里展示 `10 美金以下` 与 `10 美金以上` 两组；`20-30 美金` 作为溢价空间更好的经验偏好，不写成通用规则。

## 核心判断逻辑

每个候选方向先写成一个可验证假设：

| 字段 | 示例 |
|---|---|
| 目标用户 | 户外露营用户 |
| 使用场景 | 长时间户外使用，需要便携、耐用、稳定 |
| 当前不满 | 续航不足、接口不稳、防水等级不清楚 |
| 产品方案 | 做更长续航、更稳接口、更清楚防水等级的版本 |
| 预期结果 | 用户愿意为了可靠性接受更高价格 |

再用六类证据验证：

| 证据 | 看什么 |
|---|---|
| 需求证据 | 关键词搜索量、趋势、相关流量词 |
| 成交证据 | Top100 销量、销售额、价格带、竞品表现 |
| 痛点证据 | 评论里的抱怨、QA、差评主题 |
| 供给证据 | 当前市场有没有足够产品满足这个需求 |
| 利润证据 | 采购、FBA、广告、退货、售价后是否还能赚钱 |
| 风险证据 | 商标、专利、认证、季节性、供应链、数据偏差 |

证据不足时，只能标“待验证”或“观察”，不能写成强推荐。

## 竞品池规则

| 竞品组 | 选择目的 |
|---|---|
| Top10 标杆组 | 看市场天花板、主流价格带、头部卖点、评论门槛 |
| 近半年放量新品组 | 看新品怎么起量、怎么做内容、怎么切关键词 |
| 结构补充组 | 覆盖低价、高价、高评分、差评集中、不同功能路线 |

“近半年放量新品”默认口径：

- 近半年上架
- 且 BSR 进入小类前 100，或月销量达到 Top100 月销量中位数 20% 以上
- 阈值可按品类调整

运营复核重点：

- Top10 是否真是当前类目的主流打法
- 新品组是否真的有销量，不是纯新 ASIN
- 是否漏掉不同价格带、不同功能路线、差评集中样本
- 是否混入不相关用途产品

## 利润参考测算

利润模块只做参考，运营通常会再自己核算一遍。

| 层级 | 公式 | 用途 |
|---|---|---|
| 基础 FBA 毛利 | 建议售价 - 采购价 - 头程 - FBA 费用 - 佣金 - 仓储费 - 入库配置费 | 看产品本身有没有空间 |
| 扣广告和退货后的 FBA 毛利 | 基础 FBA 毛利 - 新品广告费 - 预估退款损失 | 看新品推广期是否还能接受 |

最低字段：

| 字段 | 口径 |
|---|---|
| 建议售价 | 运营填写，或先用竞品价格带估算 |
| 采购价 | 运营/供应链填写 |
| 站点汇率 | 按调研时点汇率 |
| 实际重量/体积重 | 运营手填 |
| 预估头程费用 | 系统按计费重和渠道单价估算，运营可改 |
| FBA 费用 | 运营手填，以亚马逊后台/收入计算器为准 |
| 佣金率 | 先按 15%，实际以 Amazon 后台费率表为准 |
| 仓储费 | 早期统一按建议售价 3% 简化估算 |
| 入库配置费 | 运营手填，不确定则待补，不默认 0 |
| 广告费率 | 新品默认 20%，运营可调整 |
| 退货率 | 优先类目平均值，必须标注来源 |

每一层都必须给毛利额和毛利率。

CPC 如果来自卖家精灵关键词建议竞价，只能当广告竞争参考，不写成广告后台真实 CPC。

头程费用按 `计费重(g) / 1000 * 渠道单价` 估算，计费重取体积重和实际重的较大值。当前经验单价：美国美森 11 元/kg、美国普船 6 元/kg、加拿大尊享达 22 元/kg、加拿大海卡 9 元/kg；美国美森约等于加拿大尊享达，美国普船约等于加拿大海卡。

## 退货风险规则

退货率是早期风险提示，不是自动裁决。

| 情况 | 处理 |
|---|---|
| 细分类目退货率长期高于平均 | 标高风险，提醒运营谨慎 |
| 评论反复提到硬伤且业内长期难解决 | 标结构性问题线索，先看有没有明确改品方案 |
| 有明确改品方案 | 可以试做，但要写清验证点 |
| 没有退货率数据 | 用类目平均值，标记待复核 |

退货率来源必须标注：

- 第三方工具估算值
- 运营经验值
- 自有后台数据
- 暂用类目平均值

自有后台数据只能代表自己的产品表现，不能当作全类目精确退货率。

## 知产初筛

知产初筛前置，但只做早期风险识别。

| 类型 | 运营要看的问题 | 工具处理 |
|---|---|---|
| 外观专利 | 外形、结构、图案是否高度相似 | 标相似风险和待复核对象 |
| 实用/发明专利 | 核心功能、结构、使用方式是否可能被保护 | 标高风险线索，建议专业检索 |
| 商标 | 品牌词、标题词、功能词是否涉及注册商标 | 标禁用词或待复核词 |
| 版权 | 图片、图案、IP 形象、说明书、A+文案是否可能复制他人作品 | 标素材风险 |

工具能做：

- 根据关键词、产品名称、竞品品牌词做初筛
- 给出风险类型和检索入口
- 记录待复核项

工具不能做：

- 判断最终是否侵权
- 代替律师或代理机构意见
- 保证全网无专利风险

## 合规认证初筛

合规认证也前置，但只能写“可能需要什么材料”和“需要谁复核”。

| 产品属性 | 美国常见可能材料 | 欧盟/英国常见可能材料 | 处理 |
|---|---|---|---|
| 儿童用品/玩具 | CPSC、CPC、CPSIA、ASTM F963 | CE 玩具安全、EN71、UKCA | 强制前置 |
| 一般受 CPSC 规则约束消费品 | GCC、对应产品规则 | GPSR 或品类安全规则 | 先查标准 |
| 带电/电子产品 | FCC、UL/ETL/NRTL、能效 | CE、EMC、LVD、RoHS、UKCA | 前置复核 |
| 蓝牙/Wi-Fi/遥控/RF | FCC Certification / SDoC、FCC ID | RED、CE、UKCA | 前置复核 |
| 锂电池/含电池 | UN38.3、MSDS/SDS、UL 相关测试、运输要求 | UN38.3、RoHS、Battery Regulation | 前置复核 |
| 食品接触/厨房用品 | FDA food contact、Prop 65 | LFGB、EU food contact、REACH | 前置复核 |
| 化妆品/护肤/接触皮肤液体 | FDA 标签、MoCRA、成分和安全证明 | EU Cosmetics Regulation | 高风险 |
| 医疗/治疗/健康宣称 | FDA medical device / OTC 风险 | MDR/UK medical device 风险 | 谨慎或避开 |
| 激光/UV/辐射电子产品 | FDA CDRH radiation-emitting products | CE 及对应安全标准 | 前置复核 |
| PPE/防护用品 | NIOSH/FDA/OSHA 等视产品而定 | PPE Regulation、CE/UKCA | 高风险 |

没有产品属性时，系统不能写“低风险”，只能写“待确认”。

## 评论插件接入方式

第一版不强制采集评论。进入深挖后再接入已有插件：

`确认竞品池 -> 选择 3-5 个核心 ASIN -> 插件采集评论 -> 导出 Excel 明细和 HTML AI 报告 -> 工具读取 Excel -> 生成 VOC 证据账本`

| 插件产物 | 用法 |
|---|---|
| Excel 评论明细 | 机器分析主输入，保留原始评论、评论 ID、评分、Helpful、链接、译文 |
| HTML AI 报告 | 运营快速阅读痛点、亮点、改品建议 |

处理规则：

- Excel 明细是结构化证据源
- HTML 报告是阅读材料，不替代 Excel 证据链
- 痛点结论必须能追溯到具体评论
- 样本量不足时，只能写弱结论

## 状态定义

| 状态 | 进入条件 | 下一步 |
|---|---|---|
| 继续看 | 市场、竞品、利润、风险暂时说得通 | 报价、打样、Listing 草案、小预算验证 |
| 试做 | 有机会，但关键假设未验证 | 只验证最关键问题，不直接备货 |
| 观察 | 有趋势或痛点，但证据不足或资源暂不匹配 | 放入观察清单，定期复查 |
| 先放弃 | 利润差、风险高、无法差异化或数据反证强 | 记录原因，不继续投入 |

如果内部习惯用“立项/试做/观察/淘汰”，可以沿用旧命名；工具底层只需要保存状态和原因。

## V1 不做

| 不做 | 原因 |
|---|---|
| 不做自动爬虫 | 首版先跑通卖家精灵手动导出/导入数据和人工复核，API/MCP 后续增强 |
| 不强制评论插件采集 | 初筛阶段先轻量，值得深挖再采 |
| 不做完整图片/A+方案 | 等痛点和差异化更明确后再做 |
| 不做完整推广节奏 | V1 只保留竞品节奏痕迹和趋势参考，详细节奏放 V2 |
| 不只做底层材料 | 底层必须保留可复核的数据和判断过程，上层要能直接生成可读内容 |
| 不做最终专利/认证结论 | 只做风险初筛和待复核提示 |

## V2 深挖模块

当某个品类进入“继续看”或“试做”后，再启用这些模块：

| 模块 | 内容 |
|---|---|
| 评论 VOC 证据账本 | 评论痛点、亮点、变体问题、评论链接和权重 |
| 属性打标和交叉矩阵 | 找供给缺口和过度竞争组合 |
| 竞对推广节奏 | 价格、Coupon、Deal、BSR/Keepa、关键词变化 |
| 图片/A+方向 | 场景、痛点、卖点、对比图、模块顺序 |
| 机会评分卡 | 多个候选方向横向比较 |
| 压力测试 | 广告费率、退货率、认证成本、采购价变化下的利润变化 |

## 运营试点评估问题

第一轮只跑 1 个品类，运营重点评价：

1. 4 个必填输入是否够启动初筛？
2. 工作台卡片是否比手动拆工具更清楚？
3. 竞品池是否符合日常选竞品方式？
4. 利润参考是否够早期判断，哪些字段需要手填？
5. 退货风险只做提示、不自动淘汰，是否合适？
6. 知产/合规初筛的边界是否能接受？
7. 状态卡是否方便运营自己修改和复盘？
8. 哪些模块必须进 V1，哪些可以放 V2？
