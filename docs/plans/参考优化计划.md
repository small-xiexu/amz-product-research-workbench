### OPT-1 竞品选择逻辑说明

**现状**：阶段四（竞品边界校准）只说明要覆盖哪些 ASIN，没有要求 Claude 说明选竞品的理由。

**目标**：Claude 在进入 VOC 分析前，必须先输出竞品选择逻辑说明，让运营知道为什么选这几个竞品、分别代表什么角色。

**SKILL.md 改动位置**：阶段四「候选边界校准」章节。

**具体内容**：新增竞品选择逻辑表输出要求：

| 字段 | 说明 |
|---|---|
| ASIN | 竞品 ASIN |
| 品牌 | 品牌名 |
| 选择理由 | 为什么选这个竞品 |
| 竞品类型 | 量级标杆 / 功能差异代表 / 价格带覆盖 / 痛点参考 |
| 覆盖维度 | 该竞品代表哪个细分维度 |

覆盖要求：
- 量级标杆：至少 1-2 个（Top5 销量代表）
- 功能差异代表：每个主要功能维度至少 1 个
- 价格带覆盖：高/中/低各至少 1 个
- 痛点参考：至少 1 个（差评密集或星级偏低的产品）
- 总数：6-10 个，不得只选头部忽略长尾

**验收**：Claude 在给出 VOC ASIN 批次时，同步输出竞品选择逻辑表。

### OPT-2 差评按属性维度归类 + 三段映射输出格式

**现状**：SKILL.md 阶段六 VOC 分析输出格式要求列出首要痛点和代表性原文，但没有要求按维度归类，也没有要求给出改品方案。

**目标**：Claude 做 VOC 分析时，差评必须按属性维度归类（而非只按产品归类），并对每个维度完成三段映射：痛点 → 品牌能力 → 产品方案。

**SKILL.md 改动位置**：阶段六「评论 VOC 分析」章节的输出格式。

**具体内容**：

VOC 分析输出格式改为：

```
## 评论 VOC 分析

### [维度名称]（如：耐久性、尺寸适配、安装难度）
- 差评频次：X 条，占低分评论 Y%
- 涉及竞品：[ASIN 列表]
- 代表原文：「[1-2 条原文片段，带 review_id]」
- 是否结构性问题：是/否（判断依据）
- 产品方案：如果能解决「[痛点]」，具体方案是……

### 用户真正在意的卖点（好评高频维度）
- [维度]：[说明为什么这是核心卖点]

### 改品机会假设
基于以上维度分析，优先验证方向：……
```

要求：
- 至少归类 3 个差评维度
- 每个维度必须完成三段映射，不允许只列痛点不给方案
- 好评维度至少 2 个

**验收**：Claude 输出 VOC 分析时，结构符合上述模板，有维度归类和产品方案。

### OPT-3 交付自检清单

**现状**：SKILL.md 阶段七提到"报告生成完成后你还没有完成任务"，但没有明确的自检项目，Claude 可能在报告生成后直接结束。

**目标**：阶段七末尾加一张自检清单，Claude 必须逐项确认后才能宣布任务完成。

**SKILL.md 改动位置**：阶段七「深挖报告生成」章节末尾。

**具体内容**：

```
## 交付自检清单（全部通过才算完成）

数据完整性：
- [ ] candidate_pool 已生成，候选方向数 ≥ 1
- [ ] Top100 明细实际条数是多少？（<50 条需标注数据质量风险）
- [ ] 属性打标覆盖率是否达到 80% 以上
- [ ] 交叉分析是否覆盖至少 2 对维度组合

VOC 状态：
- [ ] 是否已接入评论 VOC（接入则说明评论数和覆盖 ASIN）
- [ ] 未接入时，是否已给出建议 VOC ASIN 批次

分析质量：
- [ ] 竞品选择逻辑表是否已输出（OPT-1）
- [ ] VOC 差评是否按维度归类并给出产品方案（OPT-2）
- [ ] Go/No-Go 判断是否有数据支撑（不允许只说"观察"不给理由）

待补项：
- [ ] 利润复核字段是否已提醒运营填写
- [ ] 知产/合规初筛是否已提醒
- [ ] 下一步最重要的 3 件事是否已明确列出

输出文件：
- [ ] report.md 已生成
- [ ] dashboard.html 已生成
- [ ] data.xlsx 已生成
```

**验收**：Claude 在报告生成后，逐项过一遍自检清单，未通过项明确标出。

### OPT-4 断点续跑指引

**现状**：SKILL.md 没有说明如果 session 中断、运营拿到半截数据时该如何恢复。

**目标**：SKILL.md 加一段断点恢复说明，运营知道每个输出文件对应哪个阶段，中断后从哪里重新开始。

**SKILL.md 改动位置**：「参考文档」章节前，加「断点续跑」段落。

**具体内容**：

```
## 断点续跑

如果 session 中断，按以下顺序恢复：

| 已有文件 | 对应阶段 | 下一步 |
|---|---|---|
| import_manifest.json | 数据盘点完成 | 运行 build_candidate_pool |
| candidate_pool.json | 候选池已生成 | 读取候选池，进入候选边界校准 |
| precheck_report.md | 预审已完成 | 确认主线方向，进入 VOC 或深挖 |
| review_voc_package.json | VOC 数据已就绪 | 读取 normalized_reviews，做 VOC 分析 |
| research_package.json | 深挖数据包已生成 | 读取数据包，生成报告 |
| final_report/report.md | 报告已生成 | 过自检清单，补利润/知产模板 |

恢复时优先读取最新的 JSON 文件，不要重新跑已完成的步骤。
```

**验收**：SKILL.md 包含上述断点续跑说明，运营在新 session 中可以按表格找到当前进度。

### OPT-5 Go/No-Go 量化评分卡

**现状**：`status_card` 只有定性状态（继续看/观察/先放弃），运营看不出判断依据。

**目标**：在 `decision_review` 里加一张五维加权评分卡，总分对应四档决策，每个维度有数据锚点。

**改动范围**：
- `build_research_package_from_candidate.py`：新增 `_build_go_nogo_scorecard()` 函数
- `research_package.json` schema：`decision_review` 增加 `go_nogo_scorecard` 字段
- `render_report.py`：Excel 新增「Go/No-Go评分卡」Sheet，Markdown 新增对应章节
- SKILL.md：综合判断输出格式引用评分卡

**评分维度**：

| 维度 | 权重 | 数据来源 |
|---|---|---|
| 市场规模 | 20% | `demand_evidence.market_avg_monthly_units` / `market_avg_monthly_revenue_usd` |
| 竞争格局 | 25% | `competition_structure.top10_product_units_share` + 新品占比 |
| 需求清晰度 | 15% | `demand_evidence.search_signal` + `trend_signal` |
| 进入壁垒（反向） | 20% | OPT-6 壁垒评估结果 |
| 盈利能力 | 20% | `profit_reference.post_ads_returns_margin` |

**决策映射**：

| 加权总分 | 决策 |
|---|---|
| 7.5-10 | GO |
| 6.0-7.4 | CONDITIONAL GO |
| 4.0-5.9 | HOLD |
| 0-3.9 | NO-GO |

**验收**：宠物牵引绳样例跑通，`research_package.decision_review.go_nogo_scorecard` 有评分数据，Excel 有「Go/No-Go评分卡」Sheet。

### OPT-6 六类进入壁垒评估表

**现状**：风险矩阵有竞争集中度、新品机会、退货风险、利润不确定性、知产/合规、数据质量，但缺少 Review 门槛（新品追平成本）、资金壁垒、供应链壁垒的系统评估。

**目标**：在 `decision_review.risk_matrix` 或新字段 `entry_barriers` 里，覆盖六类壁垒，每类有等级 + 数据依据 + 建议。

**改动范围**：
- `build_research_package_from_candidate.py`：新增 `_build_entry_barriers()` 函数
- `research_package.json` schema：新增 `entry_barriers` 字段
- `render_report.py`：Excel 新增「进入壁垒」Sheet

**六类壁垒**：

| 壁垒类型 | 数据来源 | 推算逻辑 |
|---|---|---|
| Review 门槛 | Top10 平均评分数 | >2000 = 高，500-2000 = 中，<500 = 低 |
| 资金壁垒 | 首批备货 + FBA + 头程估算 | 待运营填利润模板后计算 |
| 技术壁垒 | 知产/合规初筛结果 | 有认证要求 = 高，无 = 低 |
| 合规壁垒 | 知产/合规初筛结果 | 有强认证（UL/FCC）= 高 |
| 供应链壁垒 | 产品路线 + 退货率 | 定制件/强季节 = 高 |
| 品牌壁垒 | 头部品牌销量占比 | >40% = 高，20-40% = 中，<20% = 低 |

**验收**：`research_package.entry_barriers` 有六类数据，Excel 有「进入壁垒」Sheet。

### OPT-7 新品友好度评级

**现状**：`new_listing_opportunity` 有 `new_listing_count_6m` 和 `recent_6m_units_share`，但没有综合评级，运营需要自己判断这个市场对新品是否友好。

**目标**：在 `new_listing_opportunity` 里加 `friendliness` 字段（绿/黄/红），由脚本按阈值自动计算，报告里直接展示。

**改动范围**：
- `build_candidate_pool_from_import_manifest.py`：在组装 `new_listing_opportunity` 时加 `friendliness` 计算
- `render_report.py` / `render_candidate_pool.py`：展示新品友好度评级

**评级规则**：

| 指标 | 绿灯 | 黄灯 | 红灯 |
|---|---|---|---|
| 半年内新品占 Top100 比例 | ≥10% | 5-10% | <5% |
| 半年内新品销量占比 | ≥10% | 5-10% | <5% |
| 新品能否进入 Top50 | 有 | 不确定 | 无 |

综合评级：三项全绿=绿，有一项红=红，其余=黄。

**验收**：候选池和深挖报告里显示新品友好度评级，刮窗器和牵引绳样例结果合理。
