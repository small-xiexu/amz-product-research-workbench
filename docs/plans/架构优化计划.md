# 架构优化计划

> 创建日期：2026-06-11
> 依据：与 Claude Code 的架构 Review 对话，对照 zach22-1999/amazon-skills 项目的比较分析

## 背景

当前架构原则"脚本=数据工具，Claude=分析者"方向正确，但执行有漂移：
- 脚本层残留大量解读类函数（分级文字、建议文字、机会点生成）
- 唯一 Skill 体积过大（469行），触发粒度粗，复用性差
- 架构原则只在 memory 里，未落进项目文档

---

## P0 — 架构原则文档化

- [x] 在 `docs/` 下新建 `架构原则.md`，写清楚三层边界和脚本/Claude 分工规则
  - 验收：已创建 `docs/架构原则.md`，覆盖三层边界、分工规则、数据诚信规则、参考文档索引
  - 核心规则：脚本做计算，Claude 做解读
  - 脚本可做：字段提取、格式转换、数值计算、聚合统计、数据校验
  - 脚本不可做：分级文字、建议文字、解读文字、机会点生成
  - Skills 职责：Claude 的行为规范（角色+工作流+约束+输出格式），不包含私有脚本
  - 参考文档职责：工具调用细节（Sorftime策略、卖家精灵导出规范）
