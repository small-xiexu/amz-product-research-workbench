# 评论 VOC 导出指令完整性规范

评价插件的用户操作只需要 ASIN。系统给运营的是可复制 ASIN 清单、建议采集站点、文件存放目录和导入命令；不要让运营填写评论范围、目标条数、字段筛选、低星筛选等复杂条件。ASIN 的路线、角色、选择理由和样本缺口由系统内部记录和分析。

本项目需要用户手动导出/采集的数据只有两类：

| 类型 | 用户要做什么 | 系统必须给什么 |
|---|---|---|
| 卖家精灵 | 按指定入口导出报表 | 报表入口、站点、月份、输入对象、导出范围、`data_role`、命名和兜底 |
| 评价 | 把 ASIN 粘进评论插件并导出 | ASIN 清单、建议站点、存放目录、命名和导入命令 |

## 给运营的固定输出

```text
本轮评价数据放置目录：
<绝对路径>

评价采集：
- 采集入口：评论慢速采集助手
- 建议站点：<US / CA / UK / DE / JP ...>
- ASIN（直接复制到插件 ASIN 输入框，一行一个）：
<ASIN_1>
<ASIN_2>
<ASIN_3>
- 操作：选择站点，粘贴 ASIN，点击开始采集；完成后导出 Excel，如有 HTML 报告或 JSON 工作台导出也一并保存。
- 文件命名建议：<站点>_review_voc_<路线或批次>_<日期>.xlsx
- 导入命令：<本轮实际命令>
```

不要输出给运营：

- 评论范围
- 目标条数
- 低星评论目标
- Verified Purchase 筛选
- 必要字段清单
- 复杂字段填表说明

这些不是插件当前需要运营填写的内容。若插件默认只导出特定范围或字段，由插件和导入脚本处理；系统只在分析阶段检查评论数、低分数、字段和站点/地区口径是否足够。

## ASIN 清单生成规则

系统内部仍要说明为什么选这些 ASIN，但用户侧只看到 ASIN 列表。ASIN 应来自参考 ASIN 池、卖家精灵 Top100/Sorftime 搜索结果、新品样本、价格带代表和痛点参考。

| ASIN 角色 | 用途 | 用户侧是否展示角色 |
|---|---|---|
| `primary_reference` | 主推路线最相似竞品 | 可不展示 |
| `high_sales_benchmark` | 高销量标杆 | 可不展示 |
| `new_release_sample` | 新品或低评论仍有销量样本 | 可不展示 |
| `premium_benchmark` | 高客单或升级款样本 | 可不展示 |
| `painpoint_reference` | 评分偏低或差评集中的样本 | 可不展示 |
| `excluded_reference` | 混池/旁支对照 | 可不展示 |

内部记录要保留：

- ASIN
- 路线
- ASIN 角色
- 选择理由
- 来源：卖家精灵 / Sorftime / 人工确认
- 是否主推路线样本
- 是否混池或对照样本

## 操作步骤

给运营的说明保持短：

1. 打开评论慢速采集助手。
2. 选择建议站点。
3. 将 ASIN 清单粘贴到 ASIN 输入框，一行一个。
4. 点击开始采集，等待插件完成。
5. 导出 Excel；如有 HTML 报告或 JSON 工作台导出，也一起保存。
6. 文件放到本轮 `inputs/reviews/` 目录。

遇到登录、验证码、访问限制时，让运营按插件提示处理，不要求系统绕过。

## 导入命令

Excel / HTML：

```bash
python3 scripts/build_review_voc_from_plugin_export.py \
  <VOC输出目录> \
  <评论Excel或多个Excel> \
  <可选HTML报告> \
  --candidate-id <候选ID> \
  --candidate-name "<候选名称>"
```

JSON 工作台导出：

```bash
python3 scripts/build_review_voc_from_plugin_export.py \
  <VOC输出目录> \
  --json-input <评论JSON> \
  --candidate-id <候选ID> \
  --candidate-name "<候选名称>"
```

## 分析阶段检查

评论导入后，系统检查而不是让运营预填：

- 有效评论是否少于 30 条。
- 低分评论是否少于 10 条。
- 是否覆盖主推路线、关键价格带、新品样本和痛点参考。
- 评论采集站点和评论地区是否混在一起。
- 是否有评论 ID、ASIN、评分、日期、原文和链接。
- HTML AI 报告是否只作为辅助阅读，强证据是否能回到评论明细。

样本不足时，系统输出补抓 ASIN 清单；仍然只让运营把补抓 ASIN 粘进插件。

## 对话输出自检

发给运营前检查：

- 是否只把评价采集说成“粘贴 ASIN 到评论插件”。
- 是否给了可复制 ASIN 清单、建议站点、存放目录和导入命令。
- 是否没有要求运营填写评论范围、目标条数、字段清单或低星筛选。
- 是否把 ASIN 角色、路线、选择理由留在系统内部记录或报告解释中。
- 是否仍然把卖家精灵作为另一类手动导出处理。
