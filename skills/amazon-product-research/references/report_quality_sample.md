# Stage 12 报告质量参考

以下用通用化描述说明每个板块"好的写法"和"差的写法"的差别。目标是决策建议书，不是数据罗列。

---

## 1. Hero 板块

**好的写法：**
- 一句话给出方向性结论，不含糊。"建议进入小批量验证" / "建议补齐 X 数据后再评估" / "建议暂停推进，理由如下"
- 5-6 个关键指标（细分 TAM、大类 TAM、均价、竞品数、VOC 覆盖 ASIN 数），细分 TAM 和大类 TAM 必须分开
- 读完 Hero 就知道结论是什么、盘子多大、竞争多密
- `.lead` 保持 1-2 句精简。Hero 是"结论摘要"，不是"分析正文"。一句话说清最大机会 + 最大风险 + 建议动作即可。详细的"市场/机会/瓶颈"三段分析交给下面"资深运营评估"板块。

**lead 段落好的写法：**
```html
<p class="lead">成熟红海中的产品力机会——0新品+高评论壁垒+高EBC率意味着这不是一个能快速切入的市场，但竞品全线停留在X方案，Y升级有明确的差异化窗口。最大障碍不是市场，是数据：搜索量与流量结构全面缺失，当前无法做投放预算决策。</p>
```

**差的写法：**
- "该品类具有较大市场潜力，值得关注" — 没给明确方向
- 只有大类 TAM，没拆细分 — 运营被大盘数字带偏
- Hero 里放 10+ 个指标 — 变成数据仪表盘
- `.lead` 写 200+ 字带 `<br>` 的三段长文 — 应该放到"资深运营评估"板块，Hero 只留摘要
- **只报数据不给判断** — "月销12万件、均价$15、集中度38%"叫数据播报，不叫分析

## 2. 资深运营评估

**好的写法：**
- 紧接 Hero 下方，是报告最重要的分析板块
- 三个小节：市场判断 / 机会判断 / 瓶颈与建议
- 每节一段话，把数据串成分析故事。不是"列数字"，是"数字意味着什么"
- 关键指标加粗，让运营快速定位核心信息
- 市场判断：体量 + 壁垒本质
- 机会判断：竞品缺陷 + 差异化方案 + why now（为什么现在能切入）
- - 瓶颈与建议：最大缺口 + 严重程度 + 补数后的预期改善

**好的写法示例：**
```html
<h3>市场判断</h3>
<p>目标类目月销X万件（$X万），体量不用质疑。但近3个月<strong>0新品入榜</strong>、平均评论<strong>N条</strong>、中国卖家占<strong>Y%</strong>——这是典型的成熟红海，不是投广告就能冲进去的市场。</p>

<h3>机会判断</h3>
<p>这个市场的产品力还停留在几年前。{用户高频核心痛点描述}是必须验证的结构性问题，<strong>竞品普遍停留在低成本方案，{核心体验}没有被认真解决</strong>。{产品方案}不需要颠覆式创新，做扎实就能形成可感知差异。消费者已经在用"{好评高频词}"投票（好评X次），<strong>需求已教育、供给未跟上</strong>——这是可验证的机会窗口。</p>

<h3>瓶颈与建议</h3>
<p>关键词搜索数据全缺——CPC多少钱、流量从哪来，广告预算没法做。X路线VOC样本不足，信息量不够支撑产品决策。<strong>当前证据不足以做最终放行判断</strong>，建议补数后再评估，数据齐了判断质量会明显提升。</p>
```

**差的写法：**
- 抄 Hero 的数据换个说法再说一遍 — 没增量信息
- 按"数据来源"分类（"从卖家精灵数据看...从Sorftime数据看..."）— 这是内部审计不是运营分析
- 写"建议进一步调研" — 没说具体调研什么
- -

## 3. 产品路线对比

**好的写法：**
- 所有产品路线（含被搁置的）都出现在一张对比表中：路线名、类型（标准形态/功能升级/场景款/差异款）、优先级、判断（建议进入小批量验证/建议先验证/搁置）、一句话机会、一句话风险、**tradeoff 列（"选它就放弃了什么"）**
- 推荐路线用 green 标签，差异化路线用 amber，搁置用 gray，被否定用 red
- 表后用两张洞察卡片分别说明"当前策略"和"搁置说明"，讲清为什么选这条、为什么搁那条
- **tradeoff 列是路线对比的核心**：运营选路线不是在比谁分高，是在比"放弃的东西能不能接受"。每条路线必须写清 gain（得到什么）/ lose（放弃什么）/ best_for（适合谁做）/ worst_for（不适合谁做）
- 数据来源：`integrated_operator_judgment.json` 的 `route_recommendation` + `route_tradeoff`

**好的 tradeoff 示例：**
```
路线A-标准款：得到大盘体量确定+主流需求清晰，放弃更高价格带的溢价窗口（均价$X vs 升级款$Y）
→ 适合能承受长周期、重视稳定需求的卖家；不适合追求快进快出者

路线B-功能升级款：得到高客单+差异化空间+低竞争密度，放弃大盘体量（细分市场仅占类目Z%）
→ 适合有产品研发能力、想做品牌溢价的卖家；不适合只想铺货走量的卖家
```

**差的写法：**
- 报告只写常见形态路线，其他路线完全不提 — 运营不知道还有哪些备选方向
- 路线名只写技术词，不写业务含义 — 运营看不懂
- 搁置路线不给理由，运营以为是被否定了
- **只有评分没有 tradeoff** — 运营知道哪条分高但不知道放弃什么，做不了取舍

## 4. 类目全景

**好的写法：**
- 先给一张类目全景表，列出目标品类涉及的所有亚马逊细分类目：类目名、NodeId、Top100月销、该品类竞品数、代表ASIN及月销、均价、判断（主战场/次要战场/错误挂载）
- 全景表之后再用 2 列洞察卡片展开主战场类目（体量判断 + 季节性 + 新品信号 + 风险提示），每张卡片先给判断再给数据
- 某种品类同时出现在类目 A 和类目 B -> 两个都列，标注哪个是主战场、哪个是次要战场

**差的写法：**
- 只写一个类目，忽视其他类目下的竞品 — 漏掉了挂在别的类目下的高销量竞品
- 类目当背景一笔带过，不说是哪个 nodeId、有多少该品类的竞品
- 4 张卡片结论雷同，换个说法讲同一件事

## 5. 样本边界 / 判断口径表达

**好的写法：**
- 不作为独立固定板块展示，而是自然嵌入 Hero、类目全景、风险与下一步等业务板块
- 写清本轮判断覆盖了什么、未覆盖什么，以及哪些结论需要补样后复核
- 标注哪些是事实、哪些是推断，让运营知道结论边界在哪里
- 示例："本轮判断基于已确认样本池，未覆盖季节峰值月份，结论需在补样后复核"

**差的写法：**
- 把工具名、内部采集过程、冲突复核过程写进 HTML，让运营看到系统执行痕迹
- 不区分事实和推断，运营看完以为全是确定的
- 把样本边界单独做成固定来源板块，挤占真正的业务判断空间

## 6. 核心竞品

**好的写法：**
- 每条路线至少 2 个代表 ASIN，表中有 ASIN、品牌、月销、价格、评论数、评分、上架时间、路线、主要差评点（VOC 原文引用）、我的反击方案（具体到可写进 Listing）
- **主要差评点不是概括描述，必须有差评原文支撑**。如："{具体缺陷描述}"（差评占比Y%，N条独立评论）→ 引用原文 "{差评原文引用}"
- **反击方案必须具体到可执行**。不是"提升产品质量"，是"{具体材质/工艺方案} + {可量化测试标准} → Listing标题写 '{卖点文案}'"
- 每条弱点标注反击难度（低/中/高），让运营判断资源投入

**好的竞品弱点示例：**
```
ASIN B0XXXXXX:
  主要差评点: {具体缺陷描述}（差评Y%，N条）
  VOC原文: "{差评原文引用}" — 1星
  我的反击: {具体产品方案} + {测试标准}通过 → Listing标题写 '{卖点文案}' → A+页面放测试视频
  反击难度: 低（换材质即可，不涉及模具大改）
```

**差的写法：**
- 只列 ASIN 和品牌名，关键信息写"待补"
- 竞品选择没有覆盖全部路线
- 关键信息写"数据表现良好"这种空话
- **写"竞品质量一般"但没有差评原文** — 运营无法验证，也无法写进 Listing
- **反击方案写"要做差异化"** — 没说具体怎么做、差在哪、怎么打

## 7. 用户痛点 → 产品规格

**好的写法：**
- 必须验证 / 重点优化 / 建议优化三级优先级排序（基于提及频率和严重程度）
- 每个痛点写两句话：竞品出了什么问题 → 你的产品应该做到什么
- 这是全报告最强的部分，能直接指导打样和 Listing

**差的写法：**
- 按数据源分类而不是按优先级排序
- 只翻译评论原文，不转化为规格建议
- P0/P1/P2 阈值不写清，运营不知道为什么这样排

---

## 8. 价格带分布

**好的写法：**
- 可视化价格带 + 每个价格带的销量占比和竞品参考
- 不给拍板定价建议，只给分布
- 标注哪个价格带有切入机会，哪个价格带已被垄断

**差的写法：**
- "均价 $X，建议定价 $Y" — 定价是运营和供应链共同决定的，报告不该替运营拍板
- 只列数字没可视化

---

## 9. 关键词与流量策略

**好的写法：**
- 按购买意图分三类，不是按数据源分：
  - 主攻意图词：购买意图明确，Listing 和广告主攻
  - 可测词：量大但意图混杂，小预算验证后再决定
  - 明确否定词：流量大但与产品不相关，排除
- 每条配策略说明，不只列月搜/CPC

**差的写法：**
- 按 Sorftime / 卖家精灵数据来源分节
- 只列月搜和 CPC，不写策略建议
- 没有否定词，或否定词只写"不相关"不写原因

---

## 10. 验证路线图

**好的写法：**
- 按时间线组织，阶段数和时间跨度根据品类特征自行定义（不同品类可以是 4 阶段、6 阶段或更多阶段）
- 每步写清四个要素：**动作**（具体可执行）+ **通过标准**（可量化）+ **不通过怎么办**（失败分支，不是"重新评估"）
- 最后一步必须是明确的放行决策条件（日销≥X + ACoS<Y% + 评分≥Z → 进入小批量验证）
- 这是运营拿到报告后可以直接执行的行动计划，不是平铺的待办清单
- 数据来源：`integrated_operator_judgment.json` 的 `validation_roadmap[]`

**好的验证路线图示例（以下为通用结构示例，阶段数/时间线因品类而异）：**
```
第1周·打样验证：打样标准款+升级款各1个 → 实测卡扣5000次 → 通过标准"卡扣无变形断裂"
  → 不通过：换供应商或材质方案，不进入下一步

第2-3周·上架测CTR：上架1个Listing → Vine送30个 → 开$30/天自动广告
  → 通过标准"CTR>0.5% 且 转化率>8%"
  → 不通过：优化主图/A+/价格，再跑2周；仍不达标重新评估

第8周·放行判断：日销≥10单 + ACoS<30% + 评分≥4.2 → 进入小批量验证；否则暂停或延长验证
```

**差的写法：**
- 平铺 5-6 条"下一步"但没有时间线和先后依赖
- 写"测试产品质量""优化Listing" — 没有通过标准，运营不知道做到什么程度算通过
- 只写成功路径，不写失败分支 — 运营遇到问题不知道是该坚持还是止损
- 最后一步写"根据数据判断" — 没有具体决策阈值


## 11. 风险与放行条件

**好的写法：**
- 风险/优势双栏，至少各 3 条，每条具体可验证
- 放行条件表：条件、放行条件、暂停条件、当前状态
- 决策条件与验证路线图的第8周 exit_criteria 呼应
- 风险不写"竞争激烈"类空话，写具体："0新品入榜意味着你的Listing在搜索第一页曝光率极低"

**差的写法：**
- "风险：市场竞争激烈" — 太泛
- 放行条件表没有具体阈值，只有"是/否"
- 决策条件与验证路线图不呼应，运营看到两个不同的标准

## 写作铁律

1. **先判断后数据**。不是先列数据让运营猜。
2. **事实和推断必须分开**。价格、销量、评分是事实；关注价格带、差异点价值是推断。
3. **用词克制**。不写"护城河""几乎零竞争""不需要试错"；写"直接竞品少""短期竞争压力低""可对照验证"。
4. **不给拍板建议**。你给判断框架，运营和供应链做最终决定。
5. **内部术语不出现在 HTML 中**。Agent、MCP、tool、spawn、packet、pipeline、source_path、冲突复核过程等禁止出现。
6. **不出现品类推导链路、来源分歧与内部状态**。这些是开发过程文档，运营不需要；样本边界和判断口径可以自然嵌入业务板块。
