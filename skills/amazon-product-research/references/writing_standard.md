# 资深运营专家写作标准

本文件规定所有面向运营的产出（HTML 报告、Agent 输出中的判断字段等）的写作标准。定位：资深亚马逊运营专家在写决策建议书，不是数据分析师在写数据报告。

---

## 核心原则

**每写一句话都要想：运营看完这句话知道下一步该做什么吗？**

| # | 原则 | 说明 |
|---|---|---|
| 1 | **按路线分层，不拿大盘拍所有路线** | 类目大盘数据只反映主流形态路线。差异化形态路线有自己的竞争格局，禁止套用大盘结论 |
| 2 | **每个数据后必须跟"所以呢"** | 报数字不是分析，解释数字对卖家的含义才是分析 |
| 3 | **用运营语言，不用内部黑话** | 写"从成熟竞品中争取流量""需求已教育但供给没跟上"，不写内部枚举或情绪化比喻 |
| 4 | **诚实直接，不吓人** | 写"当前证据不足以做最终放行判断，需先补齐 X 数据"，不写夸张或惊吓式表达 |
| 5 | **把孤立数据连成故事** | 4个数字单独看没意义，串起来才构成判断 |

## 数据播报员 vs 资深运营专家

| 数据播报员写法 | 资深运营专家写法 | 差在哪 |
|---|---|---|
| "月销X万件，均价$X.XX，评论N条" | "体量不用质疑，但0新品入榜+N评论壁垒意味着进入难度极高" | 前者报数字，后者给判断 |
| "竞品使用X材料方案" | "竞品全在用低成本X方案，没有人认真做耐用性" | 前者说事实，后者说机会 |
| "好评N次提到结实耐用" | "消费者已经在用'结实耐用'投票，说明需求已教育、供给未跟上" | 前者报统计，后者揭示窗口 |
| "数据缺失，建议补充" | "当前证据不足以做最终放行判断，补齐关键词搜索量/CPC/趋势后判断质量会明显提升" | 前者说流程，后者说影响和动作 |
| "该类目竞争激烈" | "0新品入榜+N评论壁垒，说明新品需要通过差异化卖点从成熟竞品中争取流量" | 前者是废话，后者可操作 |
| "差异化机会明显" | "不需要颠覆式创新，做扎实就能产品力跳代" | 前者模糊，后者具体 |
| "市场是成熟红海（0新品+N评论）" | "主流路线是红海（0新品+高评论壁垒），但差异化路线仅1-3个竞品——竞争格局完全不同" | 前者拿大盘拍所有路线，后者按路线分层 |

## 禁止措辞

| 禁止 | 原因 | 替代写法 |
|---|---|---|
| "该品类具有较大市场潜力" | 空话，没方向 | "体量X万件/月，且X痛点明确可解决 → 值得小批量验证" |
| "建议进一步调研" | 运营不知道调研什么 | "建议补齐关键词搜索数据（搜索量/CPC/趋势），预计X天" |
| "市场竞争激烈" | 每品类都能这么说 | "0新品入榜+N评论壁垒，进入需要高门槛" |
| "数据表现良好/一般/较差" | 没阈值没判断 | "月销 > 5000件（Go线），当前3021件（差38%）" |
| "值得关注" | 最废的两个字 | 直接说"建议先验证"或"建议暂停推进"，给理由 |
| "P0安全风险 / P0痛点" | 内部标签，运营不一定理解 | "上市前必须验证的安全可靠性问题" / "用户高频核心痛点" |
| "致命弱点 / 生死考验 / 赌博" | 情绪化或惊吓式表达，影响决策沟通 | "主要差评点" / "关键风险" / "当前证据不足以直接放行" |
| "confidence Medium / final_verdict=watch / rating=blocked" | 内部枚举和字段名裸露 | "判断置信度中等" / "建议先验证" / "当前不满足放行条件" |

## 内部标签翻译（面向运营强制）

JSON 契约可以继续使用内部枚举，但写进 HTML、XLSX、`qa_notes.md` 或判断解释字段时必须翻译：

| 内部写法 | 运营可读写法 |
|---|---|
| `go` | 建议进入小批量验证 |
| `watch` | 建议先验证 |
| `no_go` / `blocked` | 建议暂停推进 / 当前不满足放行条件 |
| `high` / `medium` / `low`（置信度） | 判断置信度高 / 中等 / 偏低 |
| `strong` / `watch` / `weak` / `blocked`（评级） | 正向信号 / 需要关注 / 信号偏弱 / 当前不满足放行条件 |
| `P0` / `P1` / `P2` | 必须验证 / 重点优化 / 建议优化 |

## Hero lead 结构（强制精简）

Hero 是结论摘要，不是分析正文。`.lead` 保持 1-2 句，说清三件事：最大机会 + 最大风险 + 建议动作。详细的"市场/机会/瓶颈"分析交给下面"资深运营评估"板块。

```html
<p class="lead">成熟红海中的产品力机会——0新品+高评论壁垒+高EBC率意味着这不是一个能快速切入的市场，但竞品全线停留在X方案，Y升级有明确的差异化窗口。最大障碍不是市场，是数据：搜索量与流量结构全面缺失，当前无法做投放预算决策。</p>
```

## 各板块写作要点

| 板块 | 运营最想知道 | 写作重点 |
|---|---|---|
| Hero | 一句话，能不能做？ | 结论 + 最大机会 + 最大风险，读完30秒有判断 |
| 资深运营评估 | 凭什么这么判断？ | 市场/机会/瓶颈三小节叙事，关键数字加粗。| 产品路线对比 | 做哪条？放弃什么？ | 每条路线的机会和风险，**必须写 tradeoff"选了它就放弃了什么"**。搁置的要给重新评估条件 |
| 类目全景 | 战场长什么样？ | 主战场 vs 次要战场 vs 错误挂载，判断先行 |
| 核心竞品 | 对手弱在哪？我怎么打？ | 主要差评点要有差评原文引用，反击方案要具体到可以写进Listing |
| 用户痛点→规格 | 我的产品该做成什么样？ | 竞品出了什么问题 → 我该做到什么，可量化的规格 |
| 价格带分布 | 定什么价？ | 给分布不给拍板定价，标注机会带和垄断带 |
| 关键词策略 | 流量怎么打？ | 按意图分类（主攻/可测/否定），不按数据源分类 |
| 验证路线图 | 按什么节奏验证？ | 时间线组织，每步写清：动作 + 通过标准 + 不通过怎么办。不是平铺的待办清单 |
| 风险与放行条件 | 哪些条件满足才继续？什么情况暂停？ | 风险/优势双栏 + 明确阈值，不写"竞争激烈"类空话 |

## 自检清单

写完后对每段文字问自己：

- [ ] 这段话删掉后运营会少做一个决策吗？如果不会，删掉。
- [ ] 这段话里的每个数字后面都跟了"这意味着…"吗？
- [ ] 这段话运营看完知道下一步该做什么吗？
- [ ] 有没有"值得关注""建议调研""竞争激烈"之类的废话？
- [ ] 事实和推断分开了吗？（数字是事实，"建议定价$X"是推断）
- [ ] 所有路线都获得了同等深度的分析吗？有没有哪条路线被一笔带过？
- [ ] 推荐路线是基于证据排序的，还是基于"常见形态"标签预设的？
- [ ] 路线对比表写清楚"选了它就放弃了什么"了吗？运营看完能做出取舍吗？
- [ ] 竞品弱点有差评原文支撑吗？反击方案具体到能写进Listing吗？
- [ ] 验证路线图每步都有通过标准和失败分支吗？还是只是平铺待办？
